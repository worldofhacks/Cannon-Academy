## Context

The first three skills and the ones the MVP duel actually fires. **Every template here is
symbolic** — these skills all have `minGrade < 2`, so `symbolicOnly` is `true` and a word problem
in any of these files is a bug that blocks a non-reader from playing (PLAN.md's stated reason for
the rule).

Each file is a JSON array of `Template` objects validated by `templateSchema` (T-003):

```json
{
  "id": "add_within_10_basic",
  "skill": "add_within_10",
  "text": "{a} + {b} = ?",
  "params": { "a": [0, 9], "b": [0, 9] },
  "constraints": ["a + b <= 10"],
  "answerExpr": "a + b",
  "distractors": ["a + b + 1", "a + b - 1", "a + b + 2"]
}
```

**Per-skill authoring rules — these are the pedagogy, not style:**

| skill           | answer range | required constraints                                |
| --------------- | ------------ | --------------------------------------------------- |
| `add_within_10` | `0 … 10`     | sum never exceeds 10; both addends `>= 0`           |
| `add_within_20` | `0 … 20`     | sum never exceeds 20; every displayed number `>= 0` |
| `sub_within_20` | `0 … 20`     | minuend `<= 20`; **difference never negative**      |

Shape variety (aim for the full spread rather than eight rewordings of one form): direct
`{a} + {b} = ?`; missing addend `{a} + ? = {c}`; missing first addend `? + {b} = {c}`; doubles;
near-doubles; make-ten; three-term `{a} + {b} + {c} = ?`; direct `{a} - {b} = ?`; missing
subtrahend `{a} - ? = {c}`; missing minuend `? - {b} = {c}`; and "how many more" as a symbolic
comparison (`{c} - {a} = ?`), never as prose.

**Distractor patterns to draw from** (PLAN.md names the first three): off-by-one
(`a + b + 1`, `a + b - 1`), off-by-two, wrong operation (`a - b` for an addition template and
vice versa, guarded so it stays non-negative and plausible), and forgotten-carry style
near-misses. T-005 fills any that collide on a given draw, but a template whose declared
distractors _routinely_ collide is poor content — AC-7 measures that.

## Planning Decisions

- `locked-decision` — **a floor of 8 templates per skill, no cap.** _Owner ruling D-1,
  2026-07-27._ PLAN.md previously read "15–25 golden parameterized shapes per skill" at §Questions
  while its own day-3 row said "≥8 templates/skill floor". The owner resolved it **in the source
  document**: PLAN.md:73 now reads "a floor of 8 golden parameterized shapes per skill (the build
  target; 15–25 per skill is the post-MVP content goal, not a day-3 requirement)". ARCHITECTURE.md
  §4.1 never stated a count. AC-1 enforces `>= 8` and nothing caps it. **Closed — the docs no
  longer conflict.**
- `locked-decision` — no word problems in these three files. PLAN.md gates them to grade 2+ and
  T-006 derives `symbolicOnly` from `minGrade < 2`, which is `true` for all three.
- `proposed` — every answer in these skills is a non-negative integer. Negative results are
  outside K-2 curriculum and would also make T-005's plausibility rule (which forbids negative
  decoys against a non-negative answer) produce lopsided choice sets.
- `proposed` — template ids are prefixed with their skill id (`add_within_10_*`) so ids are
  globally unique without a registry lookup, and a stray template in the wrong file is obvious.
- `proposed` — the `?` placeholder for a missing operand is a literal `?` in `text`; it is not a
  param token, so it survives T-007's "no braces remain" check unchanged.

## Acceptance Criteria

- **AC-1**: Given each of the three JSON files, when parsed with `z.array(templateSchema)`, then
  parsing succeeds and each array has at least `8` entries.
- **AC-2**: Given every template across the three files, when inspected, then its `skill` equals
  the skill named by its own file, its `id` starts with that skill id followed by `_`, and all
  ids across the three files are pairwise unique.
- **AC-3**: Given every template in these files, when inspected, then `isWordProblem` is absent
  or `false` and `readAloud` is absent or `false` — these skills are symbolic-only.
- **AC-4**: Given every template, when its `text` is scanned, then every `{name}` token names a
  key declared in that template's `params`, and every `params` key that is not referenced in
  `text` is referenced in `answerExpr` or in at least one `constraint` — no dead parameters.
- **AC-5**: Given every template, when 1,000 questions are generated from it via
  `generateQuestion` with seeds `1 … 1000`, then every call succeeds, every sampled param lies
  inside its declared inclusive range, every declared constraint evaluates `true` for the
  sampled params, the rendered `text` contains no `{` or `}`, `choices.length === 4`, all four
  choice values are pairwise distinct, and `choices[correctIndex].value` equals
  `evaluateNumber(template.answerExpr, params)`.
- **AC-6**: Given the same 1,000-sample sweep, when every correct answer is inspected, then it is
  a non-negative integer; for `add_within_10` it is `<= 10`; for `add_within_20` and
  `sub_within_20` it is `<= 20`. Additionally, every numeric token appearing in the rendered
  `text` is a non-negative integer `<= 20`.
- **AC-7**: Given the same 1,000-sample sweep per template, when the number of samples in which
  `describeDistractorSources` (T-005 AC-14) reports a `'ladder'` source is counted, then it is
  fewer than `250` of the 1,000 — a template whose declared distractors collide more than a
  quarter of the time is under-engineered content, not a passing test.
- **AC-8**: Given each template, when a single generation is run at one fixed seed, then the
  test asserts that generation's rendered `text` and correct answer value against **literal
  expected values written in the test** — e.g. `expect(q.text).toBe('7 + 5 = ?')` and
  `expect(q.choices[q.correctIndex].value).toBe(12)`. The literal must be computed by the test
  author, not read from the template, so this pins the arithmetic independently of the evaluator.
- **AC-9**: Given the three files collectively, when the distinct `text` skeletons (each
  template's `text` with every `{…}` token replaced by `#`) are counted, then there are at least
  `5` distinct skeletons per skill — the ≥8 floor cannot be met with eight copies of one shape.
- **AC-10**: Given every template, when inspected, then it declares at least `3` distractor
  expressions, and no distractor expression is textually identical to `answerExpr` or to another
  distractor in the same template.
- **AC-11**: Given every template, when `generateQuestion` is called with a seed sweep of
  `1 … 200`, then no call requires more than `MAX_PARAM_SAMPLE_ATTEMPTS` rejection samples — i.e.
  no `CONSTRAINTS_UNSATISFIED` error is ever raised. A template whose constraints are this tight
  is mis-parameterised.

  symbolic-only rule, and declared-distractor hygiene, table-driven over all three files.
