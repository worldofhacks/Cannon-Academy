## Context

The pedagogical heart of the game rendered as arithmetic: math fluency shapes the *quality* of
an action rather than gating permission to act. A correct answer always fires; how fast it came
biases the roll upward; and a slow-but-correct answer from a five-year-old still lands a
respectable volley, guaranteed by the 0.35 floor.

**Signature:**

```ts
export function answerQuality(correct: boolean, elapsedMs: number, timerMs: number): number;
export function isPerfectShot(correct: boolean, elapsedMs: number, timerMs: number): boolean;
export function resolveShot(input: {
  readonly cannon: Cannon;
  readonly correct: boolean;
  readonly elapsedMs: number;
  readonly rng: Rng;
}): readonly [ShotOutcome, Rng];

export interface ShotOutcome {
  readonly kind: 'volley' | 'misfire';
  readonly answerQuality: number;   // [0,1]
  readonly rollDamage: number;      // within [cannon.damageMin, cannon.damageMax]
  readonly bonusDamage: number;     // PERFECT_SHOT_BONUS_DAMAGE or 0
  readonly damageToEnemy: number;   // rollDamage + bonusDamage, or 0 on a misfire
  readonly damageToSelf: number;    // volatile recoil, else 0
  readonly ballCount: number;       // BASE_BALLS_PER_VOLLEY (+1 on a perfect shot), 0 on a misfire
  readonly perfectShot: boolean;
}
```

**Formula — implement exactly this:**

```
quality = correct
        ? max(ANSWER_QUALITY_FLOOR, clamp(1 - elapsedMs / timerMs, 0, 1))
        : 0
u       = nextFloat(rng)                                   // [0,1)
biased  = u * (1 - QUALITY_WEIGHT) + quality * QUALITY_WEIGHT
roll    = damageMin + round(biased * (damageMax - damageMin))
perfect = correct && elapsedMs < PERFECT_SHOT_TIMER_FRACTION * timerMs
```

On a **misfire** (`correct === false`): `rollDamage = 0`, `damageToEnemy = 0`, `ballCount = 0`,
`perfectShot = false`, and `damageToSelf = cannon.temperament === 'volatile' ? cannon.recoilDamage : 0`.
The PRNG is still advanced exactly once on a misfire, so a duel's stream stays aligned for replay.

## Planning Decisions

- `locked-decision` — `ANSWER_QUALITY_FLOOR = 0.35` for any correct answer, and
  `perfectShot` iff `elapsed < 40%` of the timer. Both are stated verbatim in ARCHITECTURE.md §4.3
  and are pedagogically load-bearing; they are never to be "tuned" without changing that document.
- `proposed` — the linear blend `u*(1-W) + q*W`. ARCHITECTURE.md §4.3 says the roll is "biased by
  answerQuality" and gives no curve. This one is monotone in quality, always inside
  `[min, max]`, and preserves genuine spread at every quality level (a fast answer is better,
  never *certain*). `QUALITY_WEIGHT` lives in `tuning.ts` (T-004) so the curve's strength is a
  slider, not a rewrite.
- `proposed` — `ShotOutcome` reports `rollDamage` and `bonusDamage` separately so AC-4 can pin
  the roll strictly inside the cannon's advertised range while the Perfect Shot bonus is allowed
  to exceed it (ARCHITECTURE.md §4.3: "+1 bonus ball").
- `proposed` — the PRNG advances once on a misfire too. Skipping the draw would make replay
  depend on correctness in a way that is easy to get subtly wrong.
- `open-question` — **Reliable vs Standard.** PLAN.md distinguishes "Reliable guns never punish a
  miss" from "Standard guns waste the turn", but at the damage layer both produce zero self-damage
  and a lost turn. Whether `reliable` is meant to grant something extra (a re-answer, no turn
  loss) is unspecified. This ticket treats them identically in `resolveShot`; if the design
  intends a difference it is duel-reducer behaviour (T-020) and needs a written rule first.

## Acceptance Criteria

- **AC-1**: Given `answerQuality(true, 0, 20000)`, then it returns `1`. Given
  `answerQuality(true, 10000, 20000)`, then it returns `0.5`. Given
  `answerQuality(true, 20000, 20000)` or `answerQuality(true, 999999, 20000)`, then it returns
  exactly `ANSWER_QUALITY_FLOOR` (0.35). Given `answerQuality(false, 0, 20000)`, then it
  returns `0`.
- **AC-2**: Given `answerQuality(true, e, 20000)` for `e` sweeping `0..20000` in steps of 100,
  then every value is in `[ANSWER_QUALITY_FLOOR, 1]` and the sequence is non-increasing.
- **AC-3**: Given `isPerfectShot(true, e, 20000)`, then it is `true` for `e = 0` and
  `e = 7999`, and `false` for `e = 8000` (exactly `0.40 * timerMs` — the boundary is strict
  `<`) and for `e = 8001`. Given `isPerfectShot(false, 0, 20000)`, then it is `false`.
- **AC-4**: Given any cannon in the catalog and any `(correct: true, elapsedMs, seed)` over
  5,000 seeded combinations, when `resolveShot` is called, then `rollDamage` is an integer with
  `cannon.damageMin <= rollDamage <= cannon.damageMax`.
- **AC-5**: Given a fixed `rng` and a fixed cannon, when `resolveShot` is called for
  `elapsedMs` sweeping `20000` down to `0` in steps of 100, then `damageToEnemy` is
  non-decreasing across the sweep.
- **AC-6**: Given `swivel_gun` (8–12) and a correct answer at `elapsedMs === timerMs`, when
  10,000 seeded shots are resolved, then every `damageToEnemy` is `>= cannon.damageMin` and the
  mean is strictly greater than `cannon.damageMin` — the floor guarantees a respectable volley
  rather than a minimum one.
- **AC-7**: Given a perfect shot, when resolved, then `perfectShot` is `true`,
  `bonusDamage === PERFECT_SHOT_BONUS_DAMAGE`,
  `damageToEnemy === rollDamage + PERFECT_SHOT_BONUS_DAMAGE`, and
  `ballCount === BASE_BALLS_PER_VOLLEY + 1`. Given a non-perfect correct shot, then
  `bonusDamage === 0`, `damageToEnemy === rollDamage`, and `ballCount === BASE_BALLS_PER_VOLLEY`.
- **AC-8**: Given a wrong answer on `swivel_gun` (reliable), when resolved, then `kind` is
  `"misfire"`, `damageToEnemy === 0`, `damageToSelf === 0`, `ballCount === 0`,
  `perfectShot === false`, and `answerQuality === 0`.
- **AC-9**: Given a wrong answer on each volatile cannon, when resolved, then
  `damageToSelf === cannon.recoilDamage` — specifically `5` for `double_broadside`, `8` for
  `powder_keg`, and `10` for `long_nine`. Given a wrong answer on any `standard` cannon, then
  `damageToSelf === 0`.
- **AC-10**: Given the same `(cannon, correct, elapsedMs, rng)`, when `resolveShot` is called
  100 times, then all 100 `ShotOutcome` values are deeply equal and all 100 returned `Rng`
  values are equal.
- **AC-11**: Given any call, correct or incorrect, when the returned `Rng` is compared with the
  input, then its `state` differs — the stream advances exactly once per shot regardless of
  correctness.
- **AC-12**: Given `resolveShot` with `elapsedMs < 0`, or a cannon with `timerMs <= 0`, then it
  throws a `RangeError`.
- **AC-13**: Given 1,000 seeded simulations in which the player fires `swivel_gun` correctly at
  exactly `0.5 * timerMs` against a starting enemy hull of
  `ENEMY_HULL_BY_ISLAND.port_sumwich`, when the number of volleys needed to bring that hull to
  `<= 0` is recorded, then the median is between `4` and `6` inclusive and every observed count
  is between `4` and `7` inclusive — PLAN.md's "duels resolve in 4–6 player volleys" and "the
  very first duel never drags".
- **AC-14**: Given any resolved outcome, when inspected, then every numeric field is a finite
  integer `>= 0` except `answerQuality`, which is a finite number in `[0, 1]`.
