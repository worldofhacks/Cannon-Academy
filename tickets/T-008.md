## Context

The pedagogical heart of the game rendered as arithmetic: math fluency shapes the *quality* of
an action rather than gating permission to act. A correct answer always fires; how fast it came
biases the roll upward; and a slow-but-correct answer from a five-year-old still lands a
respectable volley, guaranteed by the 0.35 floor.

**Signature:**

```ts
export function answerQuality(correct: boolean, elapsedMs: number, timerMs: number): number;
export function isPerfectShot(correct: boolean, elapsedMs: number, timerMs: number): boolean;
export function resolveShot(input: {
  readonly cannon: Cannon;
  readonly correct: boolean;
  readonly elapsedMs: number;
  readonly rng: Rng;
}): readonly [ShotOutcome, Rng];

export interface ShotOutcome {
  readonly kind: 'volley' | 'misfire';
  readonly answerQuality: number;   // [0,1]
  readonly rollDamage: number;      // within [cannon.damageMin, cannon.damageMax]
  readonly bonusDamage: number;     // PERFECT_SHOT_BONUS_DAMAGE or 0
  readonly damageToEnemy: number;   // rollDamage + bonusDamage, or 0 on a misfire
  readonly damageToSelf: number;    // volatile recoil, else 0
  readonly ballCount: number;       // BASE_BALLS_PER_VOLLEY (+1 on a perfect shot), 0 on a misfire
  readonly perfectShot: boolean;
}
```

**Formula — implement exactly this:**

```
range    = damageMax - damageMin
quality  = correct ? max(ANSWER_QUALITY_FLOOR, clamp(1 - elapsedMs / timerMs, 0, 1)) : 0
lowerRaw = correct
         ? damageMin + max(quality * QUALITY_WEIGHT, ANSWER_QUALITY_FLOOR) * range
         : damageMin
lower    = min(ceil(lowerRaw), damageMax)                  // integer floor for the roll
u        = nextFloat(rng)                                  // [0,1)
roll     = lower + round(u * (damageMax - lower))
perfect  = correct && elapsedMs < PERFECT_SHOT_TIMER_FRACTION * timerMs
```

**Read the `max(..., ANSWER_QUALITY_FLOOR)` carefully — it is the whole point of this ticket.**
`ANSWER_QUALITY_FLOOR` floors the *roll's lower bound*, not merely the quality input. A slow but
correct answer therefore cannot roll near `damageMin`; it rolls uniformly in the **top 65 %** of
the cannon's range. `quality` above the floor raises that lower bound further, so speed shifts the
whole distribution upward while preserving genuine spread at every quality level.

The earlier draft of this ticket blended quality with the uniform draw
(`u*(1-W) + quality*W`) and floored only the quality input. That formulation lets `u → 0` produce
a roll barely above `damageMin` for a correct answer, which contradicts ARCHITECTURE.md §4.3's
stated guarantee. It was replaced; do not reintroduce it.

On a **misfire** (`correct === false`): `rollDamage = 0`, `damageToEnemy = 0`, `ballCount = 0`,
`perfectShot = false`, and `damageToSelf = cannon.temperament === 'volatile' ? cannon.recoilDamage : 0`.
The PRNG is still advanced exactly once on a misfire, so a duel's stream stays aligned for replay.

## Planning Decisions

- `locked-decision` — `ANSWER_QUALITY_FLOOR = 0.35` for any correct answer, and
  `perfectShot` iff `elapsed < 40%` of the timer. Both are stated verbatim in ARCHITECTURE.md §4.3
  and are pedagogically load-bearing; they are never to be "tuned" without changing that document.
- `proposed` — **the quality-raised lower bound**, replacing an earlier linear blend that failed
  ARCHITECTURE.md:206's guarantee that "a slow-but-correct K kid **always lands ≥ a respectable
  mid-range volley**". ARCHITECTURE.md §4.3 says the roll is "biased by answerQuality" and gives
  no curve; this one satisfies four things the blend did not all satisfy at once: the floor binds
  the **roll** (AC-15), the roll stays inside `[min, max]` (AC-4), it is monotone in quality
  (AC-5), and speed has a measurable effect size (AC-16). `QUALITY_WEIGHT` lives in `tuning.ts`
  (T-004) so the curve's strength stays a slider.
- `proposed` — **an effect-size floor on `QUALITY_WEIGHT`, via AC-16.** Bounded only by
  `0 < w <= 1` plus monotonicity, an implementation could set `w = 0.001` and pass every other
  AC while making "answer speed aims the shot" — PLAN.md's entire differentiation pitch — a
  statistically undetectable effect. AC-16 requires the mean roll at full quality to exceed the
  mean at the floor by at least `0.10 * range`, which implies roughly `QUALITY_WEIGHT >= 0.62`.
  The `0.10` threshold is itself unsourced and is recorded as open question 2.12 in
  `.tdd-swarm/traceability.md`; it is deliberately a floor, not a target.
- `proposed` — AC-16 is scoped to cannons with `range >= 10`. On the Swivel's 4-damage range,
  integer rounding of a single roll dominates any effect-size measurement, so the assertion would
  be measuring `Math.round`, not the curve. AC-5 (monotonicity) and AC-15 (the floor) still apply
  to **every** cannon.
- `proposed` — `ShotOutcome` reports `rollDamage` and `bonusDamage` separately so AC-4 can pin
  the roll strictly inside the cannon's advertised range while the Perfect Shot bonus is allowed
  to exceed it (ARCHITECTURE.md §4.3: "+1 bonus ball").
- `proposed` — the PRNG advances once on a misfire too. Skipping the draw would make replay
  depend on correctness in a way that is easy to get subtly wrong.
- `locked-decision` — **Reliable and Standard are identical at the damage layer.** *Owner ruling
  D-4, 2026-07-27.* PLAN.md distinguishes "Reliable guns never punish a miss" from "Standard guns
  waste the turn"; the owner ruled the distinction is **flavour only** — neither deals recoil,
  both lose the turn, and there is no re-answer mechanic. `resolveShot` treats them identically
  and that is correct, not a placeholder. The owner's accompanying note — that some very powerful
  weapons *should* recoil on a wrong answer — is already satisfied by the Volatile tier
  (`double_broadside` 5, `powder_keg` 8, `long_nine` 10), pinned by T-006 AC-4 and asserted here
  by AC-9. **Closed — no new reducer transition, no new phase.**

## Acceptance Criteria

- **AC-1**: Given `answerQuality(true, 0, 20000)`, then it returns `1`. Given
  `answerQuality(true, 10000, 20000)`, then it returns `0.5`. Given
  `answerQuality(true, 20000, 20000)` or `answerQuality(true, 999999, 20000)`, then it returns
  exactly `ANSWER_QUALITY_FLOOR` (0.35). Given `answerQuality(false, 0, 20000)`, then it
  returns `0`.
- **AC-2**: Given `answerQuality(true, e, 20000)` for `e` sweeping `0..20000` in steps of 100,
  then every value is in `[ANSWER_QUALITY_FLOOR, 1]` and the sequence is non-increasing.
- **AC-3**: Given `isPerfectShot(true, e, 20000)`, then it is `true` for `e = 0` and
  `e = 7999`, and `false` for `e = 8000` (exactly `0.40 * timerMs` — the boundary is strict
  `<`) and for `e = 8001`. Given `isPerfectShot(false, 0, 20000)`, then it is `false`.
- **AC-4**: Given any cannon in the catalog and any `(correct: true, elapsedMs, seed)` over
  5,000 seeded combinations, when `resolveShot` is called, then `rollDamage` is an integer with
  `cannon.damageMin <= rollDamage <= cannon.damageMax`.
- **AC-5**: Given a fixed `rng` and a fixed cannon, when `resolveShot` is called for
  `elapsedMs` sweeping `20000` down to `0` in steps of 100, then `damageToEnemy` is
  non-decreasing across the sweep.
- **AC-6**: Given `swivel_gun` (8–12) and a correct answer at `elapsedMs === timerMs` — the
  slowest possible correct answer — when 10,000 seeded shots are resolved, then **every**
  `rollDamage` is `>= 10` and the mean is `>= 10.5`. (`10 = ceil(8 + 0.35 * 4)`.) A slow-but-
  correct answer from a five-year-old never rolls in the bottom third of the Swivel's range.
- **AC-7**: Given a perfect shot, when resolved, then `perfectShot` is `true`,
  `bonusDamage === PERFECT_SHOT_BONUS_DAMAGE`,
  `damageToEnemy === rollDamage + PERFECT_SHOT_BONUS_DAMAGE`, and
  `ballCount === BASE_BALLS_PER_VOLLEY + 1`. Given a non-perfect correct shot, then
  `bonusDamage === 0`, `damageToEnemy === rollDamage`, and `ballCount === BASE_BALLS_PER_VOLLEY`.
- **AC-8**: Given a wrong answer on `swivel_gun` (reliable), when resolved, then `kind` is
  `"misfire"`, `damageToEnemy === 0`, `damageToSelf === 0`, `ballCount === 0`,
  `perfectShot === false`, and `answerQuality === 0`.
- **AC-9**: Given a wrong answer on each volatile cannon, when resolved, then
  `damageToSelf === cannon.recoilDamage` — specifically `5` for `double_broadside`, `8` for
  `powder_keg`, and `10` for `long_nine`. Given a wrong answer on any `standard` cannon, then
  `damageToSelf === 0`.
- **AC-10**: Given the same `(cannon, correct, elapsedMs, rng)`, when `resolveShot` is called
  100 times, then all 100 `ShotOutcome` values are deeply equal and all 100 returned `Rng`
  values are equal.
- **AC-11**: Given any call, correct or incorrect, when the returned `Rng` is compared with the
  input, then its `state` differs — the stream advances exactly once per shot regardless of
  correctness.
- **AC-12**: Given `resolveShot` with `elapsedMs < 0`, or a cannon with `timerMs <= 0`, then it
  throws a `RangeError`.
- **AC-13**: Given 1,000 seeded simulations in which the player fires `swivel_gun` correctly at
  exactly `0.5 * timerMs` against a starting enemy hull of
  `ENEMY_HULL_BY_ISLAND.port_sumwich`, when the number of volleys needed to bring that hull to
  `<= 0` is recorded, then the median **and every individual observation** are between `4` and
  `6` inclusive — PLAN.md's "duels resolve in 4–6 player volleys" and "the very first duel never
  drags", with no tail tolerance beyond what PLAN.md states.
- **AC-14**: Given any resolved outcome, when inspected, then every numeric field is a finite
  integer `>= 0` except `answerQuality`, which is a finite number in `[0, 1]`.
- **AC-15**: Given **every** cannon in the catalog and any correct answer at any `elapsedMs`,
  over 5,000 seeded combinations, then
  `rollDamage >= damageMin + ANSWER_QUALITY_FLOOR * (damageMax - damageMin)`. This is
  ARCHITECTURE.md:206's pedagogical guarantee stated as an assertion: the floor binds the roll,
  not just the quality input.
- **AC-16**: Given every cannon whose `damageMax - damageMin >= 10` (`culverin`,
  `twelve_pounder`, `mortar`, `double_broadside`, `powder_keg`, `long_nine`), when 20,000 seeded
  correct shots are resolved at `elapsedMs = 0` and 20,000 at `elapsedMs = timerMs`, then the
  mean `rollDamage` of the first group exceeds the mean of the second by at least
  `0.10 * (damageMax - damageMin)`. Speed must move the damage distribution by a measurable
  amount, not merely a non-negative one.

## Test Plan

- Unit (deterministic): AC-1, AC-2, AC-3 — the quality curve, its floor, its monotonicity, and
  the Perfect Shot boundary at exactly 40%. AC-3 is the off-by-one tripwire.
- Unit (deterministic): AC-4, AC-5, AC-6, AC-15 — roll bounds over every catalog cannon,
  monotonicity in speed, and the "floored respectable volley" pedagogical guarantee. AC-15 is the
  criterion that fails if anyone reverts to a formulation where the floor only bounds `quality`.
- Unit (deterministic): AC-16 — the effect-size floor. Without it, a near-zero `QUALITY_WEIGHT`
  passes every other AC while deleting the game's core mechanic.
- Unit (deterministic): AC-7, AC-8, AC-9 — Perfect Shot bonus, and the full temperament matrix
  (reliable / standard / volatile × correct / incorrect).

- Unit (deterministic): AC-12, AC-14 — argument validation and output sanity.
- Unit (deterministic): AC-13 — the tuning-relationship simulation. This is the test that fails
  if someone retunes enemy hull or starter damage into a grind.
