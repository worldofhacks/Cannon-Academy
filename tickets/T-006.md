## Context

The bundled, offline-forever game data, plus the one module that validates it. Validation runs
at import time and **throws** — a malformed catalog must be a failed test, never a broken duel
(ARCHITECTURE.md §2: "Catalog authoring errors should fail a test, not a child's battle").

All shapes come from T-003's zod schemas. This ticket writes data against them and adds
`src/content/index.ts`, which parses each JSON through its schema and re-exports the typed
arrays plus total lookup helpers.

**`skills.json`** — nine skills, grade ranges taken from the armory's "Skill (grade band)"
column, `symbolicOnly` derived as `minGrade < 2`:

`add_within_10` 0–1 ✔symbolicOnly · `add_within_20` 1–2 ✔ · `sub_within_20` 1–2 ✔ ·
`place_value_compare` 2–2 · `two_step_add_sub` 2–3 · `mult_facts` 3–3 · `div_facts` 3–4 ·
`fractions_int` 4–5 · `multi_digit_order_ops` 5–5.

**`islands.json`** — five islands, `order` 0–4 in PLAN.md's stated arc, each carrying the range
skills and cannon unlocks that the armory's "How earned" column assigns to it. Every island
after the first sets `requiresIsland` to its predecessor (PLAN.md: crossing a mastery threshold
"lifts the fog on the next island").

**`ranks.json`** — five ranks, `tier` 0–4 in ladder order, `minWins` per the open question below.

**`crew.json`** — the three crew members PLAN.md names (Gunner, Carpenter, Cook) as identity
data only. Their gameplay passives are a **`scope-cut`**: PLAN.md states "Crew depth is a day-4
stretch: the cut line keeps chests as coins + cannons + cosmetics."

## Planning Decisions

- `locked-decision` — **Culverin recoil is `0`.** *Owner ruling D-3, 2026-07-27.* PLAN.md's armory
  writes the volatile parenthetical as a number for three guns (`Volatile (5)`, `Volatile (8)`,
  `Volatile (10)`) but as a word for the Culverin (`Volatile (crit)`), and PLAN.md §Risks says the
  K-band mitigation is that the starter gun "can't punish". The planner read "crit" as the
  Culverin's unusually wide 4–16 spread — which the T-008 damage roll already produces — rather
  than as a recoil, and the owner accepted that reading. `culverin.recoilDamage = 0`, with
  `temperament: 'volatile'` retained. AC-4 pins the three documented recoil values exactly.
  **Closed — do not reopen without a new owner ruling.**
- `proposed` — no separate `critBonus` field. ARCHITECTURE.md §4.3's damage model has no crit
  term; the only bonus it defines is the Perfect Shot bonus ball. Adding a stat the engine does
  not consume would be fabrication.
- `open-question` — **`ranks.json` `minWins` thresholds.** PLAN.md names the five ranks and says
  advancement is "by duel wins", with no numbers. AC-7 pins `cadet.minWins === 0` and strict
  increase across tiers; the actual values are the implementer's, satisfying that AC.
- `proposed` — `symbolicOnly` is derived as `minGrade < 2` rather than hand-set per skill, so it
  cannot drift from PLAN.md's "word problems gated to grade 2+" rule. AC-6 asserts the derivation.
- `proposed` — timers stored in **milliseconds** (`timerMs`), since `ANSWER_CHOSEN` carries
  `elapsedMs` (ARCHITECTURE.md §4.2). PLAN.md's seconds are multiplied by 1000.
- `proposed` — `src/content/index.ts` validates at module load and throws. The alternative
  (validate only in tests) would let a bad hand-edit reach a device; ARCHITECTURE.md §2 already
  asks for boot-time validation in dev.
- `scope-cut` — crew passive effects (Gunner crit nudge, Carpenter +5 hull between duels, Cook
  one answer re-roll), cosmetics catalog, and the harbor shop. All are PLAN.md day-4 items and
  the first is explicitly on the cut line.

## Acceptance Criteria

- **AC-1**: Given `src/content/index.ts`, when imported, then `skills`, `cannons`, `islands`,
  `ranks`, and `crew` are exported as readonly arrays whose contents have each passed the
  corresponding T-003 zod schema, and importing the module produces no thrown error.
- **AC-2**: Given `cannons`, when inspected, then it has exactly 10 entries whose ids are
  exactly the 10 `CannonId` values with no duplicates; `skills` has exactly 9 entries covering
  every `SkillId`; `islands` has exactly 5; `ranks` has exactly 5.
- **AC-3**: Given each cannon in the Context table, when looked up by id, then its `skill`,
  `damageMin`, `damageMax`, `temperament`, `timerMs`, `minGrade`, `maxGrade`, and `unlock` equal
  the table row exactly.
- **AC-4a**: Given `culverin`, then its `recoilDamage` is `0` despite its `volatile` temperament.
  *(Added by the orchestrator 2026-07-28. AC-3's field list omits `recoilDamage` and AC-4's second
  clause covers only `reliable`/`standard`, so the Culverin — the one volatile cannon that must
  not punish — was pinned by no criterion at all, only by ruling D-3's body text. The Test Agent
  asserted it anyway and flagged the gap; this makes the criterion match the frozen test.)*
- **AC-4b**: Given `crew.json`, then it contains exactly three members with unique non-empty ids,
  one each corresponding to the Gunner, Carpenter and Cook that PLAN.md names.
  *(Added by the orchestrator 2026-07-28. No criterion constrained crew contents, so AC-1 would
  have passed vacuously against an empty crew array. The Test Agent asserted the PLAN.md contents
  and flagged it as beyond literal AC text; ratified here.)*
- **AC-4**: Given the volatile cannons, when inspected, then `double_broadside.recoilDamage === 5`,
  `powder_keg.recoilDamage === 8`, and `long_nine.recoilDamage === 10`. Given every cannon whose
  `temperament` is `reliable` or `standard`, then its `recoilDamage === 0`.
- **AC-5**: Given `cannons`, when filtered to `unlock.kind === "starter"`, then the result is
  exactly `[swivel_gun, culverin]`, both share the skill `add_within_10`, both have
  `minGrade === 0`, and their damage ranges differ (`8–12` vs `4–16`) — PLAN.md's "two cannons
  on the same K skill with different profiles".
- **AC-6**: Given every skill, when inspected, then `symbolicOnly === (minGrade < 2)`, and
  `0 <= minGrade <= maxGrade <= 5`.
- **AC-7**: Given `ranks`, when sorted by `tier`, then the ids are exactly
  `[cadet, ensign, captain, commodore, fleet_legend]`, the tiers are exactly `0,1,2,3,4`,
  `cadet.minWins === 0`, and `minWins` is strictly increasing across tiers.
- **AC-8**: Given `islands`, when sorted by `order`, then the ids are exactly
  `[port_sumwich, isla_products, quotient_cove, fraction_reef, grandline]` with orders
  `0,1,2,3,4`; `port_sumwich.requiresIsland` is absent; and every other island's
  `requiresIsland` is the id of the island one `order` lower.
- **AC-9**: Given every island, when its `rangeSkills` and `unlocksCannons` are checked, then
  every referenced `SkillId` exists in `skills` and every referenced `CannonId` exists in
  `cannons`; and for every cannon whose `unlock.kind === "range"`, that cannon appears in
  exactly one island's `unlocksCannons`, and that island's id equals the cannon's `unlock.island`.
- **AC-10**: Given every cannon, when its `skill` is resolved in `skills`, then the skill exists
  and the cannon's `[minGrade, maxGrade]` equals the skill's `[minGrade, maxGrade]`.
- **AC-11**: Given `getCannon(id)`, `getSkill(id)`, `getIsland(id)`, and `getRankByTier(tier)`,
  when called with a valid key, then each returns the matching entry; when called with a value
  outside the union or an unknown tier, then each throws an `Error` naming the missing key —
  never returns `undefined` (the callers run under `noUncheckedIndexedAccess` and must not
  need a null check).
**`validateCatalogs` signature — ratified by the orchestrator 2026-07-28.** AC-12 did not pin it,
so the Test Agent chose one and froze it rather than leaving the implementer to guess a different
shape. The binding signature is **one argument, an object keyed by catalog name** —
`{ skills, cannons, islands, ranks, crew }` holding the raw arrays — throwing an `Error` whose
message names the catalog key and the offending entry's `id`. Ratified rather than re-opened: it
is a reasonable reading, it is already frozen, and re-freezing costs more than it is worth.

- **AC-12**: Given a deliberately corrupted catalog object (e.g. a cannon with
  `damageMax < damageMin`) passed to the exported `validateCatalogs` function, when called, then
  it throws an error whose message names the offending catalog and entry id.
- **AC-13**: Given `src/content/index.ts` and every catalog JSON file, when their text is
  scanned, then none contains the substrings `http://` or `https://` — content is bundled and
  the play path never reaches the network (ARCHITECTURE.md §4.4). This scan is secondary
  defence; the authoritative guard for the determinism half of this ticket's DoD is the repo
  ESLint block (`no-restricted-properties` on `Math.random`, `no-restricted-globals` on `Date`),
  which as of Phase 0 covers **both** `src/engine/**` and `src/content/**` and is verified
  firing. A grep cannot see `const { random } = Math`; the lint rule can.
- **AC-14**: Given each island, when its `rangeSkills` and `unlocksCannons` are compared against
  a table hardcoded in the test, then they match exactly:
  `port_sumwich` → skills `[add_within_20, sub_within_20, two_step_add_sub]`, cannons
  `[six_pounder, chain_shot, double_broadside]`; `isla_products` → `[mult_facts]`,
  `[twelve_pounder]`; `quotient_cove` → `[div_facts]`, `[mortar]`; `fraction_reef` →
  `[fractions_int]`, `[powder_keg]`; `grandline` → `[multi_digit_order_ops]`, `[long_nine]`.
  T-010 AC-12 and T-011 AC-7 have frozen tests that assume exactly this assignment; without this
  criterion T-006 has latitude those tickets do not.
