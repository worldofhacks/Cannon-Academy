## Context

Every question is four taps: one correct answer and three wrong ones. A template supplies its
distractors as expressions (`["a + b + 1", "a + b - 1", "a * b"]`) evaluated against the same
sampled parameters as the answer. Two things can go wrong and both are pedagogical failures:

1. A distractor **collides** — it evaluates to the answer, or to another distractor. With
   `a = 2, b = 2`, `"a + b"`, `"a * b"`, and `"a + b + 0"` are all `4`. Two identical taps make
   the question unanswerable and, worse, mark a correct understanding wrong.
2. A distractor is **implausible** — `a + b = 7` offered against `700` or `-3` is free to
   eliminate, so a correct tap stops meaning anything (PLAN.md §The duel loop: multiple choice
   is only defensible because the distractors are engineered).

This module owns exactly that: evaluate the candidate expressions, reject collisions, enforce
plausibility, and — when a template's own distractors are insufficient for a particular
parameter draw — fill the remainder from a deterministic near-miss ladder rather than failing
the whole question.

Consumes `evaluateNumber` / `ExprError` from T-002 (`@engine/questions/expr`), `Template` from
`@content/schemas`, `QuestionGenerationError` from `@engine/questions/types`, and
`DISTRACTOR_MAX_RATIO` / `DISTRACTOR_ABS_FLOOR` / `MAX_DISTRACTOR_ATTEMPTS` / `CHOICE_COUNT`
from T-004. **This module does not shuffle** — ordering is the generator's job (T-007), because
the shuffle must consume the same PRNG stream as parameter sampling.

**Plausibility rule (the operational definition of "plausibly typed"):** a candidate `d` is
plausible against answer `x` when all of the following hold.

```
1. Number.isFinite(d)
2. Number.isInteger(d) === Number.isInteger(x)          — same numeric type as the answer
3. d >= 0 whenever x >= 0                                — no negative decoys for K-5 arithmetic
4. |d - x| <= DISTRACTOR_ABS_FLOOR                       — near miss ...
   OR |d| <= |x| * DISTRACTOR_MAX_RATIO
      AND |d| >= |x| / DISTRACTOR_MAX_RATIO              — ... or same order of magnitude
```

**Near-miss fill ladder**, tried in this fixed order, first plausible non-colliding value wins —
exactly **9 rungs**, which is why T-004 AC-4 requires `MAX_DISTRACTOR_ATTEMPTS >= 9`:
`x+1, x-1, x+2, x-2, x+10, x-10, x*2, x+3, x-3`.

**The zero-answer case is the binding constraint on `DISTRACTOR_ABS_FLOOR`.** It is not exotic:
`sub_within_20` legally samples `a == b`, giving an answer of `0`. At `x = 0` clause 4's
magnitude-ratio branch is undefined (`|x| * RATIO == 0`), so plausibility collapses to
`0 <= d <= DISTRACTOR_ABS_FLOOR`. Evaluating the ladder at `x = 0` gives
`1, -1, 2, -2, 10, -10, 0, 3, -3`; clause 3 removes every negative, `x*2 = 0` collides with the
answer, and `x+10 = 10` is out of reach unless the floor is `>= 10`. **The complete set of values
the ladder can ever yield for a zero answer is `{1, 2, 3}`** — so `DISTRACTOR_ABS_FLOOR` must be
at least `3` or a four-choice question is unbuildable. T-004 AC-5 pins that floor. At exactly `3`
there is **zero headroom**: all three values are needed, which is what AC-13 asserts directly.

## Planning Decisions

- `proposed` — the plausibility rule above. ARCHITECTURE.md §4.1 says "plausibly typed (same
  magnitude/sign)"; that is prose. This is the smallest rule that means it, and every threshold
  it uses is a named T-004 constant rather than a literal.
- `proposed` — the fill ladder. ARCHITECTURE.md requires distinct, non-equal distractors but
  does not say what to do when a template's own list collides on a particular draw. The
  alternatives were (a) reject the parameter draw and resample, or (b) fill. Fill is chosen
  because it keeps the failure local and deterministic; rejection would let a single unlucky
  template silently starve its skill's question pool.
- `proposed` — the ladder is ordered, not random, so the same `(template, params)` always
  yields the same choice set. This is what makes the T-019 golden suite meaningful and what
  lets a replayed duel reproduce the exact question a child saw.
- `locked-decision` — never return fewer than `CHOICE_COUNT - 1` distractors; throw instead.
  A three-choice question would break the 2×2 answer grid contract (ARCHITECTURE.md §3.6).

## Acceptance Criteria

- **AC-1**: Given a template with `answerExpr "a + b"`, distractors `["a + b + 1",
"a + b - 1", "a * b"]`, and params `{ a: 3, b: 4 }`, when `buildDistractors` is called, then
  it returns exactly 3 values, `[8, 6, 12]`, in the template's declared order.
- **AC-2**: Given a candidate that evaluates equal to the answer (params `{ a: 2, b: 2 }`, where
  `"a * b"` equals `"a + b"` equals `4`), when called, then the returned set contains no value
  equal to the answer, and still has exactly 3 values.
- **AC-3**: Given two template distractors that evaluate to the same number for the sampled
  params, when called, then the returned values are pairwise distinct.
- **AC-4**: Given any successful call, when the answer is prepended to the result, then all
  `CHOICE_COUNT` values are pairwise distinct.
- **AC-5**: Given a template distractor that violates the plausibility rule (e.g. `"a * b * 1000"`
  against an answer of `7`), when called, then that value is excluded from the result and
  replaced from the fill ladder, and every returned value satisfies the plausibility rule
  against the answer.
- **AC-6**: Given an answer of `0`, when called, then the magnitude-ratio branch is skipped
  rather than dividing by zero, no returned value is negative, and every returned value `d`
  satisfies `1 <= d <= DISTRACTOR_ABS_FLOOR` — asserted against the constant itself, with no
  arithmetic offset baked into the assertion.
- **AC-7**: Given a template whose declared distractors all collide or are all implausible,
  when called, then it returns 3 values drawn from the fill ladder in ladder order, all distinct
  and all plausible.
- **AC-8**: Given a template whose `distractors` list is exhausted and whose fill ladder cannot
  produce 3 distinct plausible values within `MAX_DISTRACTOR_ATTEMPTS`, when called, then it
  throws a `QuestionGenerationError` with `code` `DISTRACTOR_FAILURE` naming the template id —
  it never returns a short list, a duplicate, or the answer.
- **AC-9**: Given a template distractor expression that references an unknown identifier, when
  called, then the `ExprError` from T-002 propagates unchanged (it is a content authoring bug
  and must fail the T-019 golden suite loudly, not be silently swallowed by the fill ladder).
- **AC-10**: Given the same `(template, params)` pair, when `buildDistractors` is called 100
  times, then all 100 results are element-wise identical — the function is pure and consumes no
  randomness.
- **AC-11**: Given a non-integer answer (e.g. `3.5` from `"a / b"` with `{ a: 7, b: 2 }`), when
  called, then every returned value is non-integer, and given an integer answer, then every
  returned value is an integer.
- **AC-12**: Given `isPlausibleDistractor(candidate, answer)` exported for reuse, when called
  with `NaN` or `Infinity` as the candidate, then it returns `false`.
- **AC-13**: Given a template whose `answerExpr` evaluates to `0` for the sampled params — for
  example `"a - b"` with `{ a: 5, b: 5 }`, the case a legal `sub_within_20` draw produces — when
  `buildDistractors` is called, then it returns exactly 3 values, all distinct, none equal to
  `0`, and the returned set is exactly `{1, 2, 3}` when `DISTRACTOR_ABS_FLOOR === 3`. It must
  **not** throw `DISTRACTOR_FAILURE`. This is the case that starves if `DISTRACTOR_ABS_FLOOR`
  or `MAX_DISTRACTOR_ATTEMPTS` is set too low, and it is reachable from real content.
- **AC-14**: Given `describeDistractorSources(template, params)` exported alongside
  `buildDistractors`, when called, then it returns a `readonly ('declared' | 'ladder')[]` of
  length 3, aligned index-for-index with `buildDistractors`' result, marking each returned value
  by where it came from. For AC-1's clean case all three entries are `'declared'`; for AC-7's
  total-collision case all three are `'ladder'`.
