## Context

The fast lane of progression, and the smallest complete gameplay loop in the codebase: a fixed
number of questions on one skill, answered, with mastery filling at **full rate** (unlike a duel,
which fills at half). PLAN.md is explicit that this is "a meter, not a new mode" — so there is no
opponent, no hull, no damage, and no cannon. Just questions and a meter.

```ts
export interface DrillSession {
  readonly skillId: SkillId;
  readonly rng: Rng;
  readonly length: number; // total questions in the drill
  readonly answered: number;
  readonly correct: number;
  readonly recentTemplateIds: readonly string[];
  readonly mastery: SkillMastery; // updated at full rate after each answer
  readonly current: Question | null; // null once complete
  readonly complete: boolean;
  readonly log: readonly DrillAnswer[];
}
export interface DrillAnswer {
  readonly templateId: string;
  readonly choiceIndex: number | null; // null = timed out
  readonly correct: boolean;
  readonly elapsedMs: number;
}

export function startDrill(input: {
  readonly skillId: SkillId;
  readonly templates: readonly Template[];
  readonly mastery: SkillMastery;
  readonly rng: Rng;
  readonly length: number;
}): DrillSession;

export function answerDrill(
  session: DrillSession,
  choiceIndex: number | null, // null means the timer expired
  elapsedMs: number,
): DrillSession;
```

`answerDrill` grades the answer against `current.correctIndex`, applies
`applyAnswer(mastery, 'range', correct)` from T-010, appends to `log`, pushes the answered
template id onto `recentTemplateIds`, and either generates the next question or marks the session
complete. It is pure: same input session, same result.

## Planning Decisions

- `proposed` — **`src/engine/drill.ts` is a module not named in ARCHITECTURE.md §8's engine
  list.** §8 names the `app/range.tsx` screen but no engine counterpart; putting the pure loop in
  the engine follows §3.2's rule that all game logic lives outside React, and it serves an
  explicit MVP-checklist line.
- `locked-decision` — range answers fill mastery at `MASTERY_RATE_RANGE` (full). PLAN.md.
- `proposed` — `length` is a caller parameter, not a tuning constant. Neither document states a
  drill length; inventing one in `tuning.ts` would be fabrication, and the range screen may
  legitimately want different lengths per island. Validated `>= 1`.
- `proposed` — a timeout is expressed as `choiceIndex === null`; **D-8 / T-036**: it does **not** count as an incorrect
  attempt**: `attempts` increments, `weightedCorrect` does not. This matches the duel's
  `TIMER_EXPIRED` semantics (a miss, not a skip), so a child cannot farm accuracy by waiting.
  No timer is _run_ here — `elapsedMs` is passed in, per the engine's no-`Date` rule.
- `proposed` — `answerDrill` on a complete session throws rather than silently no-op'ing.
  Unlike the duel reducer (whose out-of-phase events are no-ops by design, because a UI can
  legitimately race), a drill answer after completion is a caller bug.
- `proposed` — the drill does **not** resolve unlocks. It returns the updated `SkillMastery`;
  the caller passes it to `resolveUnlocks` (T-010). One concern per module.
- `proposed` — templates are injected, as in T-007, so the drill has no dependency on the
  content registry (T-019) and is testable with two fixtures.
- `proposed` — `recentTemplateIds` is **most-recent-first** (newest at index 0), matching
  T-007 `generateQuestion` / `eligiblePool` (`slice(0, RECENT_TEMPLATE_WINDOW)`). Ticket
  prose "pushes" means record the answered id at the front of the list, not append-only.

## Acceptance Criteria

- **AC-1**: Given `startDrill` with `length: 10` and a valid template pool, when called, then
  `answered === 0`, `correct === 0`, `complete === false`, `current` is a non-null `Question`
  whose four choices are distinct, and `mastery` deeply equals the input mastery.
- **AC-2**: Given `startDrill` with `length: 0`, a negative or non-integer `length`, or an empty
  `templates` array, when called, then it throws — a `RangeError` for the length cases and the
  T-007 `QuestionGenerationError` with `code` `NO_TEMPLATE` for the empty pool.
- **AC-3**: Given a session, when `answerDrill(session, session.current.correctIndex, 1000)` is
  called, then `answered === 1`, `correct === 1`, `mastery.weightedCorrect` increased by
  `MASTERY_RATE_RANGE` (1.0), `mastery.correct === 1`, and `mastery.attempts === 1`.
- **AC-4**: Given a session, when answered with a wrong `choiceIndex`, then `correct` stays `0`,
  `mastery.weightedCorrect` is unchanged, and `mastery.attempts` increased by `1`.
- **AC-5**: ~~Given a session, when answered with `choiceIndex === null` (timeout), then the answer
  is recorded with `correct: false` and `choiceIndex: null`, `mastery.attempts` increased by `1`~~
  **Superseded by D-8 / T-036**: a timeout charges neither mastery attempts nor correct, does not
  advance `answered`, keeps the same `current` question, and only appends a log entry.

- **AC-6**: Given a session, when answered with a `choiceIndex` outside `[0, 3]` or a negative
  `elapsedMs`, then it throws a `RangeError` and the session is not advanced.
- **AC-7**: Given a `length: 10` drill answered 10 times, when the final session is inspected,
  then `answered === 10`, `complete === true`, `current === null`, and `log.length === 10`.
- **AC-8**: Given a completed session, when `answerDrill` is called again, then it throws an
  `Error` naming the completed state.
- **AC-9**: Given a drill of length 10 answered correctly 10 times starting from
  `emptyMastery`, when the final `mastery` is inspected, then `isMastered(mastery)` is `true`
  and `meterPercent(mastery)` is `100` — this is PLAN.md's MVP-checklist path from a practice
  drill to a cannon unlock.
- **AC-10**: Given a drill of length 10 answered correctly 5 times and incorrectly 5 times, when
  the final mastery is inspected, then `isMastered` is `false` — accuracy `0.5` is below the
  `0.70` gate even though the meter has filled halfway.
- **AC-11**: Given a template pool of 8 and a drill of length 20, when every question's
  `templateId` is recorded in order, then no id repeats within any window of
  `RECENT_TEMPLATE_WINDOW` consecutive questions.
- **AC-12**: Given the same `startDrill` input and the same sequence of `(choiceIndex, elapsedMs)`
  answers, when the drill is run twice, then the two final sessions are deeply equal — including
  every generated question — and running with a different seed produces a different question
  sequence.
- **AC-13**: Given any session, when `answerDrill` is called, then the input session object is
  not mutated (its `answered`, `mastery`, and `log` are unchanged after the call).
- **AC-14**: Given any `DrillSession`, when round-tripped through
  `JSON.parse(JSON.stringify(session))`, then it is deeply equal to the original — a drill can be
  interrupted and restored.
