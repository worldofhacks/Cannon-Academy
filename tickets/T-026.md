## Context

Wave-1 integration found that two merged modules disagree about one invariant:

- `templateSchema` (T-003) accepts **three or more** distractors — `distractors: string[] (>=3)`,
  pinned by T-003 AC-4 as "at least three".
- `assertQuestion` (T-003) requires a `Question` to carry **exactly four** choices.

So a template authored with four distractors **validates cleanly**, and only fails later when the
five-choice `Question` built from it is rejected. It fails safe, but late — and the error surfaces
far from the catalog line that caused it.

The origin is the ticket spec, not the implementation: T-003's AC-4 asked for `>= 3` and the
implementer built exactly that. ARCHITECTURE.md §4.1 is unambiguous that the game is
four-choice universally, which means exactly three distractors.

**Owner decision, 2026-07-28: tighten the schema.** Do it now, before T-014/T-015/T-016 author
roughly 72 templates against it — a catalog author should get an immediate, located error rather
than a downstream one.

This ticket touches file scopes disjoint from every other wave-2 ticket (`T-004` owns
`src/engine/tuning.ts`; `T-006` owns `src/content/*.json` and `src/content/index.ts`), so it runs
in parallel safely.

## Planning Decisions

- `locked-decision` (owner, 2026-07-28) — exactly three distractors, not a minimum.
- `corrected` (orchestrator, 2026-07-28) — **an earlier revision of this ticket claimed the frozen
  suite asserts a 4-distractor template parses successfully, and authorised the Test Agent to
  invert that assertion. That claim was false.** The Test Agent probed it before acting — grepping
  every occurrence of `distractor` across all four historical revisions of
  `__tests__/content/schemas.test.ts` — and found no such assertion has ever existed. The only
  "accepts" fixture in any revision uses exactly three. The wave-1 integration report's
  "confirmed empirically" came from an ad-hoc probe script, not a frozen test.
  **The over-permissive behaviour lives only in `src/content/schemas.ts`'s `.min(3)`.** No frozen
  test needs inverting, and the Test Agent's change was purely additive: five new tests, zero
  existing lines touched, all 90 pre-existing T-003 assertions and tags intact.
  This ticket therefore needs no frozen-test edit at all.
- `proposed` — no other distractor property changes. Distinctness, plausibility, and the
  never-equal-to-the-answer rule live in T-005 and are out of scope here.

## Acceptance Criteria

- **AC-1**: Given a template object with exactly three distractors, when parsed by
  `templateSchema`, then `safeParse` returns `success: true`.
- **AC-2**: Given a template object with **four** distractors, when parsed, then `safeParse`
  returns `success: false`, and the issue path is exactly `["distractors"]`.
- **AC-3**: Given a template object with two distractors, when parsed, then `safeParse` returns
  `success: false` — the existing lower-bound behaviour is unchanged.
- **AC-4**: Given the parsed type, then `Template['distractors']` remains `string[]` with element
  type `string` — tightening the count must not loosen or change the element type.
- **AC-5**: Given every other schema and every other field, when the full T-003 frozen suite runs,
  then it passes **entirely unchanged** — this ticket changes one invariant and nothing else.
