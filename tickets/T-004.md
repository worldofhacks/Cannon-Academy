## Context

`tuning.ts` is the one file the day-5 tuning pass and the hidden `app/dev.tsx` slider screen
read. Everything downstream imports named constants from here; **no other engine module may
contain a literal feel-number.** This ticket therefore defines the *complete* constant surface
up front, so no later ticket has to reach back and edit this file.

**This ticket is the project's honesty boundary.** PLAN.md and ARCHITECTURE.md fix some numbers
exactly and leave others unspecified. The rule applied here:

- **Specified** → the constant equals the documented value and an AC asserts exact equality.
- **Unspecified** → the constant still exists with a name, and the ACs pin its *behaviour*
  (bounds, ordering, monotonicity, ratios). The implementer picks a value that satisfies the
  ACs; **the ACs are the contract, the number is not.** Every unspecified number is also listed
  for the human in `.tdd-swarm/traceability.md` under Open Questions.

Do not invent a documented-looking value for anything in the second group and do not write a
comment claiming a source that does not exist.

**Required export surface** (grouped; keys typed against T-003's id unions):

```

Damage:    ANSWER_QUALITY_FLOOR, PERFECT_SHOT_TIMER_FRACTION, QUALITY_WEIGHT,
           BASE_BALLS_PER_VOLLEY, PERFECT_SHOT_BONUS_DAMAGE
```

## Planning Decisions

- `locked-decision` — one file, no per-domain constant files (ARCHITECTURE.md §4.3 / §8).
- `locked-decision` — values fixed by the docs: `PLAYER_HULL = 100`,
  `ANSWER_QUALITY_FLOOR = 0.35`, `PERFECT_SHOT_TIMER_FRACTION = 0.40`,
  `MAX_PARAM_SAMPLE_ATTEMPTS = 100`, `CHOICE_COUNT = 4`,
  `MASTERY_THRESHOLD_CORRECT = 10`, `MASTERY_MIN_ACCURACY = 0.70`,
  `MASTERY_RATE_RANGE = 1.0`, `MASTERY_RATE_DUEL = 0.5`,
  `MERCY_LOSS_STREAK_TRIGGER = 2`, `MERCY_FORCED_MISFIRES = 2`.
- `open-question` — **enemy hull beyond the first island.** PLAN.md gives only "40–50 at the
  start" and "enemy hulls scale by island". Pinned by AC-2 (first island in `[40, 50]`, strictly
  increasing by island order) rather than by invented values.
- `open-question` — **`ONBOARDING_ENEMY_HULL`.** PLAN.md promises the tutorial sloop "politely
  sinks in three volleys" but gives no hull. The `ENEMY_HULL_BY_ISLAND` entry for `port_sumwich`
  cannot serve: T-008 AC-13 tunes it to a 4–6 volley duel. A separate named constant exists so
  the out-of-scope onboarding wiring reads it instead of inventing a literal, which would break
  ARCHITECTURE.md §4.3's one-constants-file rule. Pinned by AC-12.
- `proposed` — **T-004's tests must not import `@content`.** T-006 is a same-wave sibling and its
  files do not exist in this ticket's worktree. Wherever an AC needs catalog-derived context
  (island order, the Swivel's damage range) the test hardcodes it as a literal. Stated in AC-2
  and AC-12 so a test author does not reach for `@content` and get an unresolvable import.
- `open-question` — **coin payout formula.** PLAN.md says "coins by performance (win, accuracy,
  perfects)" and "losing ... still pays a small purse", with no numbers. Pinned by AC-6.
- `open-question` — **chest rarity weights.** PLAN.md names no tiers and no weights. Pinned by
  AC-7 (three tiers, positive, summing to 1, strictly decreasing by rarity).
- `open-question` — **bot mercy margin, accuracy window, and per-band accuracy clamps.**
  PLAN.md says "minus a margin (clamped to the band)" with no numbers. Pinned by AC-8.
- `open-question` — **recent-template exclusion window size.** ARCHITECTURE.md §4.1 says
  "excluding recently served ids" without a count. Pinned by AC-4.
- `proposed` — `QUALITY_WEIGHT` is the blend factor between the uniform roll and answer
  quality in T-008's damage formula. ARCHITECTURE.md §4.3 says the roll is "biased by
  answerQuality" but gives no curve. Pinned by AC-3 and by T-008's monotonicity ACs.
- `proposed` — `MASTERY_METER_MAX = 100` to match the Firestore field `mastery: {skillId: 0-100}`
  (ARCHITECTURE.md §5).
- `open-question` — `DOUBLE_SHOT_TIMER_FACTOR` and `DOUBLE_SHOT_VOLLEY_COUNT`. PLAN.md describes
  Double-Shot as opting into "a harder variant of the same skill for a second volley" and defines
  neither "harder" nor the volley count numerically. T-022 models "harder" as a shortened timer
  on the same question; the factor and count are named here and pinned only by AC-5b.
- `proposed` — `DISTRACTOR_MAX_RATIO` / `DISTRACTOR_ABS_FLOOR` operationalise "plausibly typed
  (same magnitude/sign)" from ARCHITECTURE.md §4.1, which is prose, not a rule. Pinned by AC-5
  and consumed by T-005.

## Acceptance Criteria

- **AC-1**: Given the module, when the documented constants are read, then
  `PLAYER_HULL === 100`, `ANSWER_QUALITY_FLOOR === 0.35`,
  `PERFECT_SHOT_TIMER_FRACTION === 0.4`, `MAX_PARAM_SAMPLE_ATTEMPTS === 100`,
  `CHOICE_COUNT === 4`, `MASTERY_THRESHOLD_CORRECT === 10`,
  `MASTERY_MIN_ACCURACY === 0.7`, `MASTERY_RATE_RANGE === 1`, `MASTERY_RATE_DUEL === 0.5`,
  `MASTERY_METER_MAX === 100`, `MERCY_LOSS_STREAK_TRIGGER === 2`, and
  `MERCY_FORCED_MISFIRES === 2`.
- **AC-2**: Given `ENEMY_HULL_BY_ISLAND`, when inspected, then it has exactly one entry for
  each of the five `IslandId` values; every value is a positive integer; the value for
  `port_sumwich` is in `[40, 50]` inclusive; and reading the values in ascending island `order`
  (`port_sumwich, isla_products, quotient_cove, fraction_reef, grandline`) yields a strictly
  increasing sequence. **The test must hardcode that island order as a literal array** — it must
  not read `order` from `@content/islands.json`, because T-006 is a same-wave sibling and its
  worktree does not exist here.
- **AC-3**: Given `QUALITY_WEIGHT`, when inspected, then `0 < QUALITY_WEIGHT <= 1`.
  Given `BASE_BALLS_PER_VOLLEY`, then it is an integer `>= 1`. Given
  `PERFECT_SHOT_BONUS_DAMAGE`, then it is an integer `>= 1`.
- **AC-4**: Given `RECENT_TEMPLATE_WINDOW`, when inspected, then it is an integer `>= 1` and
  `<= 8` (it must stay below the ≥8-templates-per-skill floor so a skill's pool can never be
  fully excluded — PLAN.md day-3 "≥8 templates/skill floor"). Given `MAX_DISTRACTOR_ATTEMPTS`,
  then it is an integer `>= 9` — T-005's near-miss fill ladder has exactly 9 fixed rungs, and a
  smaller bound makes the later rungs unreachable, which silently reintroduces the zero-answer
  starvation this constant exists to prevent.
- **AC-5**: Given `DISTRACTOR_MAX_RATIO`, when inspected, then it is a finite number `> 1`.
  Given `DISTRACTOR_ABS_FLOOR`, then it is an integer `>= 3` — derived, not chosen: for a zero
  answer T-005's magnitude-ratio branch is undefined and negatives are excluded, so the only
  plausible distractors the fill ladder can ever produce are `{1, 2, 3}`. A floor below `3`
  leaves fewer than the three distinct distractors a four-choice question requires, and a legal
  `sub_within_20` draw (`a == b`) hits it. See the derivation in T-005's Context.
- **AC-6**: Given the economy constants, when inspected, then `COINS_WIN_BASE`,
  `COINS_LOSS_BASE`, `COINS_PER_ACCURACY_PERCENT`, and `COINS_PER_PERFECT_SHOT` are all finite
  numbers `> 0`, and `COINS_LOSS_BASE < COINS_WIN_BASE` — losing pays, but pays less
  (PLAN.md: "losing never drops your rank and still pays a small purse").
- **AC-7**: Given `CHEST_RARITY_WEIGHTS`, when inspected, then it has exactly one entry per
  `ChestRarity`; every weight is `> 0`; the weights sum to `1` within `1e-9`; and
  `weights.common > weights.uncommon > weights.rare`. Given `CHEST_COIN_RANGE_BY_RARITY`, then
  each rarity maps to `{ min, max }` integers with `0 < min <= max`, and both `min` and `max`
  are strictly increasing across `common → uncommon → rare`.
- **AC-8**: Given the opponent constants, when inspected, then `BOT_ACCURACY_WINDOW` is an
  integer `>= 1`; `0 < BOT_MERCY_MARGIN < 1`; and `BOT_ACCURACY_BAND_BY_GRADE` has exactly one
  entry per `GradeBand` with `0 < min < max <= 1` for each. Reading the bands in the order
  `k_1, g2_3, g4_5` yields a non-decreasing sequence of `min` values and of `max` values — an
  older band's bot is never easier than a younger band's.
- **AC-9**: Given every exported value, when the module is loaded twice, then each export is
  the same reference / value (the module holds no mutable state), and every object-valued
  export (`ENEMY_HULL_BY_ISLAND`, `CHEST_RARITY_WEIGHTS`, `CHEST_COIN_RANGE_BY_RARITY`,
  `BOT_ACCURACY_BAND_BY_GRADE`) is frozen — mutating a key throws in strict mode.
- **AC-10**: Given every numeric export, when inspected, then none is `NaN`, `Infinity`, or
  `-Infinity`, and every constant documented as an integer satisfies `Number.isInteger`.
- **AC-11**: Given `DOUBLE_SHOT_TIMER_FACTOR`, when inspected, then it is a finite number with
  `0 < DOUBLE_SHOT_TIMER_FACTOR < 1` — opting into Double-Shot must shorten the timer, never
  lengthen it. Given `DOUBLE_SHOT_VOLLEY_COUNT`, then it is an integer `>= 2` — PLAN.md's
  "a second volley".
- **AC-12**: Given `ONBOARDING_ENEMY_HULL`, when inspected, then it is a positive integer
  strictly less than `ENEMY_HULL_BY_ISLAND.port_sumwich`, and small enough that three volleys at
  the Swivel Gun's *guaranteed floor* damage sink it — formally
  `ONBOARDING_ENEMY_HULL <= 3 * Math.ceil(8 + ANSWER_QUALITY_FLOOR * (12 - 8))`, with the
  Swivel's `8`/`12` hardcoded in the test for the same same-wave reason as AC-2. This is
  PLAN.md's "a scripted pirate sloop that politely sinks in three volleys" expressed as a named
  constant, rather than left for whoever wires `app/onboarding.tsx` to invent as a bare literal
  outside `tuning.ts`.

## Amendments from the Test Agent's pre-freeze review (orchestrator, 2026-07-28)

The Test Agent flagged these rather than inventing interpretations. All are ratified; the frozen
tests already assert the corrected form.

- **AC-4 contradicted its own rationale at exactly 8.** The criterion said
  `RECENT_TEMPLATE_WINDOW <= 8`, and gave the reason as "must stay **below** the ≥8-templates-per-
  skill floor so a skill's pool can never be fully excluded". At exactly 8, a skill sitting on the
  floor has its **entire** pool excluded, T-007's fallback fires on every call, and the recency
  feature becomes a permanent no-op. **Corrected to `<= 7`.** (LESSONS.md L-005: a bound is a
  contract, and the worst legal value must still satisfy every consumer.)
- **AC-8's `BOT_ACCURACY_WINDOW >= 1` was unsatisfiable for its own consumer.** T-021 AC-3 is
  written as "a history of 8 correct and 2 incorrect (with `BOT_ACCURACY_WINDOW >= 10`) … returns
  0.8" — impossible at the worst legal value of 1, where mercy degenerates to a coin flip on the
  last answer. **Corrected to `>= 10`.**
- **AC-3, AC-6 and AC-8 pinned direction without magnitude** — the exact L-006 pattern. AC-3's
  `0 < QUALITY_WEIGHT <= 1` is satisfied by `0.001`, which makes speed-aimed damage statistically
  invisible while every criterion passes. The effect size was deferred to T-008 AC-16, two waves
  after this constant freezes. **Derived and asserted here instead**, in closed form from T-008's
  own formula: the binding constraint is `QUALITY_WEIGHT > 7/12 ≈ 0.5833`, set by `culverin` and
  `double_broadside`. The same hole at `COINS_PER_ACCURACY_PERCENT` / `COINS_PER_PERFECT_SHOT`
  (`> 0` survives `1e-9`, which vanishes under T-009's `Math.round`) and at `BOT_MERCY_MARGIN`
  (`0 < m < 1` survives `1e-9`) is closed the same way.
- **AC-9's freeze requirement is DEEP, not shallow.** `as const` freezes nothing at runtime, and a
  shallow `Object.freeze` leaves `CHEST_COIN_RANGE_BY_RARITY.common.min = 999` working. Ratified
  as a strengthening of "mutating a key throws".
- **AC-2 gains an upper bound on enemy hull.** The criterion pinned `port_sumwich` to `[40,50]`
  and required monotone growth, but nothing bounded later islands — `grandline: 1e9` was legal and
  would make the final duel unwinnable. `proposed` by the orchestrator, not derived from a source
  doc: **no island hull may exceed `4 * PLAYER_HULL`.** This leaves ample room for a boss node
  (PLAN.md §Encounters) while making an unwinnable value impossible. Flagged for the owner in
  traceability §2 — it is a balance ceiling, not a mechanic.
- **AC-7's chest-rarity separation is bounded in practice, not in text.** No floor separates the
  tiers beyond reachability, so `rare: 1e-9` reads as legal. In practice the frozen 100,000-draw
  seeded reachability test fails long before that, so the test is the effective floor. Recorded
  rather than adding a second, redundant bound.

- **AC-12 floor corrected (orchestrator, 2026-07-28).** AC-12 pinned only a **ceiling** on
  `ONBOARDING_ENEMY_HULL` (`<= 3 × floor damage = 30`). The shipped value of `24` satisfies every
  frozen assertion and still **sinks in two volleys**, breaking PLAN.md:75's promise that the
  guided sloop "politely sinks in three volleys": with the Swivel Gun, any answer inside the
  Perfect-Shot window — the normal case in a tutorial that points at the correct tap — deals 12–13,
  so two volleys reach 24 deterministically. Even floored-slow, two max rolls hit exactly 24.
  **The correct window is `[27, 30]`** — strictly above `2 × (SWIVEL_DAMAGE_MAX + PERFECT_SHOT_BONUS)`
  and at or below AC-12's existing ceiling. The frozen test reached for this floor but stopped one
  volley short, excluding only a one-volley tutorial and omitting the perfect-shot bonus. L-005
  again: a bound that constrains one side is satisfied by the worst value on the other.
- **Rider for T-018 (guided onboarding).** No legal hull can guarantee three volleys if the player
  may fire the **Culverin** — `2 × 17 = 34` exceeds AC-12's own ceiling. **The guided duel must
  restrict the player to the Swivel Gun.** Recorded on T-018 as a constraint, not left implicit.
