## Context

`tuning.ts` is the one file the day-5 tuning pass and the hidden `app/dev.tsx` slider screen
read. Everything downstream imports named constants from here; **no other engine module may
contain a literal feel-number.** This ticket therefore defines the *complete* constant surface
up front, so no later ticket has to reach back and edit this file.

**This ticket is the project's honesty boundary.** PLAN.md and ARCHITECTURE.md fix some numbers
exactly and leave others unspecified. The rule applied here:

- **Specified** → the constant equals the documented value and an AC asserts exact equality.
- **Unspecified** → the constant still exists with a name, and the ACs pin its *behaviour*
  (bounds, ordering, monotonicity, ratios). The implementer picks a value that satisfies the
  ACs; **the ACs are the contract, the number is not.** Every unspecified number is also listed
  for the human in `.tdd-swarm/traceability.md` under Open Questions.

Do not invent a documented-looking value for anything in the second group and do not write a
comment claiming a source that does not exist.

**Required export surface** (grouped; keys typed against T-003's id unions):

## Planning Decisions

- `locked-decision` — one file, no per-domain constant files (ARCHITECTURE.md §4.3 / §8).
- `locked-decision` — values fixed by the docs: `PLAYER_HULL = 100`,
  `ANSWER_QUALITY_FLOOR = 0.35`, `PERFECT_SHOT_TIMER_FRACTION = 0.40`,
  `MAX_PARAM_SAMPLE_ATTEMPTS = 100`, `CHOICE_COUNT = 4`,
  `MASTERY_THRESHOLD_CORRECT = 10`, `MASTERY_MIN_ACCURACY = 0.70`,
  `MASTERY_RATE_RANGE = 1.0`, `MASTERY_RATE_DUEL = 0.5`,
  `MERCY_LOSS_STREAK_TRIGGER = 2`, `MERCY_FORCED_MISFIRES = 2`.
- `open-question` — **enemy hull beyond the first island.** PLAN.md gives only "40–50 at the
  start" and "enemy hulls scale by island". Pinned by AC-2 (first island in `[40, 50]`, strictly
  increasing by island order) rather than by invented values.
- `open-question` — **coin payout formula.** PLAN.md says "coins by performance (win, accuracy,
  perfects)" and "losing ... still pays a small purse", with no numbers. Pinned by AC-6.
- `open-question` — **chest rarity weights.** PLAN.md names no tiers and no weights. Pinned by
  AC-7 (three tiers, positive, summing to 1, strictly decreasing by rarity).
- `open-question` — **bot mercy margin, accuracy window, and per-band accuracy clamps.**
  PLAN.md says "minus a margin (clamped to the band)" with no numbers. Pinned by AC-8.
- `open-question` — **recent-template exclusion window size.** ARCHITECTURE.md §4.1 says
  "excluding recently served ids" without a count. Pinned by AC-4.
- `proposed` — `QUALITY_WEIGHT` is the blend factor between the uniform roll and answer
  quality in T-008's damage formula. ARCHITECTURE.md §4.3 says the roll is "biased by
  answerQuality" but gives no curve. Pinned by AC-3 and by T-008's monotonicity ACs.
- `proposed` — `MASTERY_METER_MAX = 100` to match the Firestore field `mastery: {skillId: 0-100}`
  (ARCHITECTURE.md §5).
- `open-question` — `DOUBLE_SHOT_TIMER_FACTOR` and `DOUBLE_SHOT_VOLLEY_COUNT`. PLAN.md describes
  Double-Shot as opting into "a harder variant of the same skill for a second volley" and defines
  neither "harder" nor the volley count numerically. T-022 models "harder" as a shortened timer
  on the same question; the factor and count are named here and pinned only by AC-5b.
- `proposed` — `DISTRACTOR_MAX_RATIO` / `DISTRACTOR_ABS_FLOOR` operationalise "plausibly typed
  (same magnitude/sign)" from ARCHITECTURE.md §4.1, which is prose, not a rule. Pinned by AC-5
  and consumed by T-005.

## Acceptance Criteria

- **AC-1**: Given the module, when the documented constants are read, then
  `PLAYER_HULL === 100`, `ANSWER_QUALITY_FLOOR === 0.35`,
  `PERFECT_SHOT_TIMER_FRACTION === 0.4`, `MAX_PARAM_SAMPLE_ATTEMPTS === 100`,
  `CHOICE_COUNT === 4`, `MASTERY_THRESHOLD_CORRECT === 10`,
  `MASTERY_MIN_ACCURACY === 0.7`, `MASTERY_RATE_RANGE === 1`, `MASTERY_RATE_DUEL === 0.5`,
  `MASTERY_METER_MAX === 100`, `MERCY_LOSS_STREAK_TRIGGER === 2`, and
  `MERCY_FORCED_MISFIRES === 2`.
- **AC-2**: Given `ENEMY_HULL_BY_ISLAND`, when inspected, then it has exactly one entry for
  each of the five `IslandId` values; every value is a positive integer; the value for
  `port_sumwich` is in `[40, 50]` inclusive; and reading the values in ascending island `order`
  (`port_sumwich, isla_products, quotient_cove, fraction_reef, grandline`) yields a strictly
  increasing sequence.
- **AC-3**: Given `QUALITY_WEIGHT`, when inspected, then `0 < QUALITY_WEIGHT <= 1`.
  Given `BASE_BALLS_PER_VOLLEY`, then it is an integer `>= 1`. Given
  `PERFECT_SHOT_BONUS_DAMAGE`, then it is an integer `>= 1`.
- **AC-4**: Given `RECENT_TEMPLATE_WINDOW`, when inspected, then it is an integer `>= 1` and
  `<= 8` (it must stay below the ≥8-templates-per-skill floor so a skill's pool can never be
  fully excluded — PLAN.md day-3 "≥8 templates/skill floor"). Given `MAX_DISTRACTOR_ATTEMPTS`,
  then it is an integer `>= 1`.
- **AC-5**: Given `DISTRACTOR_MAX_RATIO`, when inspected, then it is a finite number `> 1`.
  Given `DISTRACTOR_ABS_FLOOR`, then it is an integer `>= 1`.
- **AC-6**: Given the economy constants, when inspected, then `COINS_WIN_BASE`,
  `COINS_LOSS_BASE`, `COINS_PER_ACCURACY_PERCENT`, and `COINS_PER_PERFECT_SHOT` are all finite
  numbers `> 0`, and `COINS_LOSS_BASE < COINS_WIN_BASE` — losing pays, but pays less
  (PLAN.md: "losing never drops your rank and still pays a small purse").
- **AC-7**: Given `CHEST_RARITY_WEIGHTS`, when inspected, then it has exactly one entry per
  `ChestRarity`; every weight is `> 0`; the weights sum to `1` within `1e-9`; and
  `weights.common > weights.uncommon > weights.rare`. Given `CHEST_COIN_RANGE_BY_RARITY`, then
  each rarity maps to `{ min, max }` integers with `0 < min <= max`, and both `min` and `max`
  are strictly increasing across `common → uncommon → rare`.
- **AC-8**: Given the opponent constants, when inspected, then `BOT_ACCURACY_WINDOW` is an
  integer `>= 1`; `0 < BOT_MERCY_MARGIN < 1`; and `BOT_ACCURACY_BAND_BY_GRADE` has exactly one
  entry per `GradeBand` with `0 < min < max <= 1` for each. Reading the bands in the order
  `k_1, g2_3, g4_5` yields a non-decreasing sequence of `min` values and of `max` values — an
  older band's bot is never easier than a younger band's.
- **AC-9**: Given every exported value, when the module is loaded twice, then each export is
  the same reference / value (the module holds no mutable state), and every object-valued
  export (`ENEMY_HULL_BY_ISLAND`, `CHEST_RARITY_WEIGHTS`, `CHEST_COIN_RANGE_BY_RARITY`,
  `BOT_ACCURACY_BAND_BY_GRADE`) is frozen — mutating a key throws in strict mode.
- **AC-10**: Given every numeric export, when inspected, then none is `NaN`, `Infinity`, or
  `-Infinity`, and every constant documented as an integer satisfies `Number.isInteger`.
- **AC-11**: Given `DOUBLE_SHOT_TIMER_FACTOR`, when inspected, then it is a finite number with
  `0 < DOUBLE_SHOT_TIMER_FACTOR < 1` — opting into Double-Shot must shorten the timer, never
  lengthen it. Given `DOUBLE_SHOT_VOLLEY_COUNT`, then it is an integer `>= 2` — PLAN.md's
  "a second volley".
