## Context

Verified against the shipped catalogs:

```
grade-0 skills:  add_within_10          <- exactly one
  swivel_gun   reliable  recoil=0
  culverin     volatile  recoil=0       <- "volatile" but cannot punish
```

Both K-1 cannons teach the **same skill**, and because both carry `recoilDamage: 0`, they differ
only in variance. PLAN.md promises "choose a cannon" is "a real decision from the first duel", and
the game's stated differentiator is that **difficulty is a strategic choice**. At grade 0 there is
no difficulty choice available — there is only one kind of sum in the game.

The external design review reached the same conclusion independently and proposed pulling the
Culverin from K-1, which would leave a kindergartener with exactly one button.

## Planning Decisions

- `locked-decision` (owner-facing recommendation, orchestrator 2026-07-28) — **add rather than
  replace.** Keep both existing starters and add a third K-1 cannon on a new `sub_within_10`
  skill:

  | cannon | skill | profile | the decision it offers |
  |---|---|---|---|
  | `swivel_gun` | `add_within_10` | 8–12 reliable | a sure thing |
  | `culverin` | `add_within_10` | 4–16 volatile, recoil 0 | same maths, a gamble |
  | **new** | **`sub_within_10`** | reliable | **different maths** |

  This preserves PLAN.md's variance-as-choice intent *and* adds the maths choice the game rests
  on. Three cannons is also exactly the duel tray's capacity, so no loadout selection is needed at
  K-1 (see T-030).
- `open-question` — the new cannon's id, display name, and exact damage band. PLAN.md's armory
  table does not contain a third K-1 gun, so these are **invented, not transcribed**, and must be
  tagged as such in the catalog citation. Suggested: a reliable band comparable to the Swivel's
  8–12 so the two reliable guns differ by *skill*, not by power.
- `proposed` — `sub_within_10` gets `symbolicOnly: true` and `minGrade: 0`, matching
  `add_within_10`. K-1 templates are symbolic-only per ARCHITECTURE §4.1.

## Why this is not "a JSON edit"

`SKILL_IDS` and `CANNON_IDS` are frozen union types in `src/content/schemas.ts`, and merged tests
pin **exact members, exact order, and exact counts** (T-003 AC-1; T-006 AC-2 pins 9 skills and 10
cannons). Adding an entry to either changes two review-passed contracts. The Test Agent amends the
frozen assertions; the Implementation Agent does not.

Doing this **before wave 5** matters: T-014/T-015/T-016 author roughly 72 templates against these
skill ids, and T-014 will need `sub_within_10` templates that do not exist yet.

## Acceptance Criteria

- **AC-1**: Given `SKILL_IDS`, then it contains `sub_within_10`, and every frozen assertion pinning
  the skill id set, its order, and its count is updated to match — no assertion deleted.
- **AC-2**: Given `CANNON_IDS`, then it contains the new K-1 cannon id, with the same treatment.
- **AC-3**: Given `skills.json`, then `sub_within_10` has `minGrade: 0`, `maxGrade` matching
  `add_within_10`'s, and `symbolicOnly: true`.

  `temperament: 'reliable'`, `recoilDamage: 0`, `unlock: { kind: 'starter' }`, and a damage band
  comparable to `swivel_gun`'s so the two reliable starters differ by skill rather than power.
- **AC-5**: Given the starter set, then it contains **exactly three** cannons, covering **two**
  distinct skills, with at least two distinct temperaments.
- **AC-6**: Given grade-band coverage, then grades 0–5 remain covered with no gap.
- **AC-7**: Given every cross-reference invariant already asserted by T-006 (bidirectional unlock
  agreement, every skill taught by ≥1 cannon, island chain integrity), then all still hold.
- **AC-8**: Given the full repo suite, then it passes — every count, order, and membership
  assertion updated deliberately, none deleted to make room.
