## Context

`TICKETS.md`, `APP-TICKETS.md`, HANDOFF, README, and ticket frontmatter disagree about counts and
status. Individual ticket files contain the actual acceptance criteria and lifecycle state, but
there is no reliable cross-track view.

## Planning Decisions

- **[locked-decision]** Individual ticket frontmatter is authoritative per ticket.
  `tickets/INDEX.md` is the only canonical cross-track view and is generated from those files.
- **[locked-decision]** Historical planning documents may link to the index but may not maintain
  competing live status tables.
- **[locked-decision]** The generator is deterministic and fails on duplicate IDs, malformed
  frontmatter, unknown lifecycle values, missing dependencies, or an output diff.

## Acceptance Criteria

- **AC-1**: Given all `tickets/T-*.md` and `tickets/app/A-*.md`, when the generator runs, then the
  index includes every ticket exactly once with track, title, status, wave, dependencies, branch,
  and source link.
- **AC-2**: Given duplicate IDs, missing dependencies, or invalid status, when
  validated, then the command exits nonzero and identifies the offending ticket.
- **AC-3**: Given unchanged ticket files, when generated twice, then output is byte-identical and
  sorted deterministically.
- **AC-4**: Given a manually stale index, when the check mode runs, then it exits nonzero without
  silently rewriting it.
- **AC-5**: Given the real repository, then A-038 through A-041 are present and the intentionally
  absent T-023 is flagged rather than silently inferred from a numeric range.

## Test Plan

- Unit/fixture (deterministic): parsing, validation, duplicate/dependency failures, ordering, and
  check-mode drift.
- Repository integration: generate the real index and verify every ticket path.

## Definition of Done

- [ ] Tests are RED, independently reviewed, and frozen before implementation.
- [ ] No hand-maintained count is treated as canonical.
- [ ] Local gates, code review, and Security Agent review pass.

## Out of Scope

Rewriting the prose in every documentation file, GitHub Issue mirroring, or changing ticket
lifecycle semantics.
