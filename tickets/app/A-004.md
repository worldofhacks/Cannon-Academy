## Context

`firebase` is installed and imported by nothing. The checklist requires progress to persist "under
the same anonymous UID", and the README already names the trap: the Firebase JS SDK defaults to
**in-memory** auth on React Native and mints a new UID on every cold start — forking cloud identity
while local progress still looks correct.

## Acceptance Criteria

- **AC-1**: Given a first launch, when auth initialises, then an anonymous user is created and its
  UID is retrievable.
- **AC-2**: Given a force-quit and relaunch, when auth initialises, then the UID is identical to
  the previous run, across at least two relaunches.
- **AC-3**: Given no network, when auth initialises, then the app degrades to local-only play and
  no screen blocks.
- **AC-4**: Given auth configured with `getAuth()` instead of `initializeAuth` + React Native
  persistence, when the test runs, then it fails — the trap is asserted against, not just avoided.

## Test Plan

- Unit (deterministic): AC-1, AC-3, AC-4 with the Firebase SDK faked at the module boundary.
- Manual (recorded): AC-2 across two real cold starts on the simulator, logged in the ticket.
