## Context

The checklist reads "grade picker → name/flag" and the flag half is not decoration. Board 5b
specifies that the onboarding flag **becomes the ship's default pennant**, so a child's ship is
already theirs before the first chest ever drops. Six flag sprites ship in the design project and
none are used.

The curated captain-name wordlist was explicitly descoped by the owner as non-MVP, so this is free
text with a safe default.

## Acceptance Criteria

- **AC-1**: Given a chosen name and flag, when committed, then both persist and survive relaunch.
- **AC-2**: Given a chosen flag, when a duel renders, then the player ship's pennant uses that
  flag's colour.
- **AC-3**: Given the screen is skipped or the name left blank, when committed, then a usable
  default captain exists — never an empty name.
- **AC-4**: Given the six flags, when rendered at 16pt, then each is distinguishable from the other
  five by hue alone.

## Test Plan

- Unit (deterministic): AC-1, AC-3 against the store; AC-2 as a props assertion on the ship
  cosmetics resolver.

- Visual (design-fidelity, NOT frozen): verified against the named board at the 375pt reference
  width, and at 360×640 / 390×844 / 430×932. Recorded as a screenshot diff in the ticket, reviewed

## Scope amendment — 2026-07-28

The original scope was `app/name-flag.tsx` alone. The A-006 Test Agent found that AC-2 (flag becomes
the pennant) and AC-4 (six distinguishable flags) cannot be satisfied from a screen file: they need a
flag palette and a cosmetics resolver that are testable headless. Both are added above.

**A-001's file is touched by exactly one line.** `src/stores/player.ts` must additionally export
`DEFAULT_CAPTAIN_NAME` and have `setNameAndFlag` substitute it for an empty trimmed name. That file
belongs to A-001, so per the skill's exclusive-scope rule this is NOT added to A-006's scopes — the
orchestrator makes that one-line change on the integration branch before dispatching A-006, and the
implementer treats it as existing API.

Why the default belongs at COMMIT and not in `emptyCaptain()`: `flow.ts` reads an empty name as
"not yet asked" and routes to this screen. Defaulting at construction makes the screen permanently
unreachable — nobody is ever asked. Leaving the bare `.trim()` makes "skip" produce `name: ''`,
which routes straight back here, so the skip button silently does nothing. Commit-time substitution
is the only placement that satisfies both, and skip must default the FLAG too or `flow.ts` loops on
the null flag instead.
