## Context

The former hardcoded "Chain Shot" defect was removed by A-022. The victory panel now truthfully
projects applied coins and mastery unlocks, but it still does not show a seeded chest rarity or
the acquisition result introduced by A-032. Board 7c adds a non-reader-friendly rarity treatment.

Board 5b's constraint matters here: cosmetics are the only drop that can never affect a duel, which
makes them the one reward safe to hand out at any accuracy, to any band.

## Acceptance Criteria

- **AC-1**: Given a victory settled by A-032, when the chest opens, then the panel renders that
  retained settlement's rarity and contents without rolling or granting anything itself.
- **AC-2**: Given the same supplied A-032 receipt across renders/remounts, when the panel projects
  it, then the announced rarity and applied contents are byte-equivalent and no roll is requested.
- **AC-3**: Given the three `CHEST_RARITIES`, when the rarity look-up table in
  `src/theme/chestRarity.ts` is read, then each rarity maps to a named token triple (fill, border,
  label colour) drawn from `src/theme/tokens.ts`, the three fills are pairwise distinct, and the
  chest panel takes its styling from that table rather than from a literal — so the tier is carried
  by colour and not only by the word.
- **AC-4**: Given A-032 settled a duplicate cannon as a coin fallback, when the chest renders, then
  it shows only that truthful coin result and never names the duplicate cannon.
- **AC-5**: Given the chest is opened repeatedly or the panel remounts, when it renders, then it
  performs no store mutation and the retained settlement remains unchanged.

## Test Plan

- Unit (deterministic): every AC. The roll is seeded, so AC-2 is an equality assertion, not a
