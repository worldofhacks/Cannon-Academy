## Context

The victory panel currently shows a hardcoded "Chain Shot" and a coin count. `rollChest` exists,
is seeded, and has weights and per-rarity coin ranges that nothing calls. Board 7c adds the gem
tier the chest was missing.

Board 5b's constraint matters here: cosmetics are the only drop that can never affect a duel, which
makes them the one reward safe to hand out at any accuracy, to any band.

## Acceptance Criteria

- **AC-1**: Given a victory, when the chest opens, then its contents come from `rollChest` with the
  duel's seeded rng.
- **AC-2**: Given the same seed, when the chest is rolled twice, then the contents are identical.
- **AC-3**: Given a rare roll, when it is displayed, then the rarity is legible as a distinct visual
  tier, not only as a word.
- **AC-4**: Given a cannon already owned, when it is rolled, then the drop degrades to coins rather
  than granting a duplicate.
- **AC-5**: Given the chest is opened, when the contents are granted, then they persist.

## Test Plan

- Unit (deterministic): every AC. The roll is seeded, so AC-2 is an equality assertion, not a
  statistical one.

- Visual (design-fidelity, NOT frozen): verified against the named board at 375pt and at
  360×640 / 390×844 / 430×932, screenshot evidence attached. **Posture-gated deferral** — no
  component-test harness exists for the app layer (`.tdd-swarm/posture.md`).
