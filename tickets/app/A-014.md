## Context

`src/services/questions.ts` is a stopgap written so the duel screen had something to ask before the
engine's generator existed. Its own header says it has no template pool, no recency window and no
distractor plausibility rules, and that it must not reach a child.

The engine side is now complete — T-007 landed `generateQuestion` and T-014/T-015/T-016 landed the
nine template files — and **nothing in the duel calls any of it.** Every question in a duel today is
fake. (The gunnery range is already on the real generator; see the blocker note below.)

**This is a rewrite of `questions.ts`, not a swap.** The earlier claim that it was "a swap rather
than a rewrite" has been deleted, because it would mislead an implementer into budgeting an
afternoon for an import change. The call site is stable and the module behind it is not: the shapes
differ (`Question` vs `DuelQuestion`), the pool has to be loaded and validated, distractors move
from a hand-built ladder to T-005's, and the recency window is state that has to be threaded through
the duel reducer because the current signature has nowhere to carry it. What survives unchanged is
`nextQuestion`'s _name and position_ in the graph — nothing in `src/components/` moves.

The interface this consumes:

```ts
// @engine/questions/generator
generateQuestion(input: {
  templates: readonly Template[];
  recentTemplateIds: readonly string[];
  rng: Rng;
}): readonly [Question, Rng]; // Question.choices is readonly Choice[] — {value, label}
```

## Planning Decisions

- **The adapter keeps the app-facing `DuelQuestion` type and projects the engine's `Question` onto
  it.** Resolved by the A-014 Test Agent; recorded here so nobody re-opens it. `QuestionPanel.tsx`
  reads `question.choices` as bare numbers (`choices.slice(0, 2)` then `value === question.answer`)
  and A-008's frozen `__tests__/app/duel-outcome.test.ts` does the same
  (`wrongChoice(choices: readonly number[], …)`). Changing `DuelQuestion.choices` to `Choice[]`
  would edit a frozen test and a component in another ticket's scope for no behavioural gain. The
  projection is `choices: q.choices.map((c) => c.value)` and
  `answer: q.choices[q.correctIndex].value` — the same projection `app/range.tsx` already performs.
- **`DuelQuestion` gains `templateId`, and `readAloud` starts coming from the engine.**
  `templateId` is what AC-3 asserts on and what the reducer prepends to its recency list; there is
  no other way to observe the window from the app layer.
- **The recency window forces a `src/stores/duel.ts` change, which is why this ticket owns that
  file.** `nextQuestion(skill, rng)` has nowhere to carry recency, so `DuelState` gains
  `recentTemplateIds: readonly string[]` and `PICK_CANNON` prepends the drawn `templateId` —
  exactly what `src/engine/duel/reducer.ts` already does. An adapter holding module-level recency
  state instead would break replay-from-seed, which is the one property the whole engine is built
  around.
- **The template pool is extracted, not duplicated.** `src/services/range.ts` already holds a
  validated `Record<SkillId, readonly Template[]>` built from nine static JSON imports. It moves to
  `src/services/templatePools.ts` verbatim and both callers import it. A second table is a drift
  hazard the moment a tenth skill lands, and it is the same nine files either way. `range.ts` is
  A-009's file and A-009 is finished, so this is a cross-wave handover, not a scope collision.

## Blocked-on note — read before dispatching

**The adversarial plan review recorded this ticket as BLOCKED on engine ticket T-019 (template
registry), on the grounds that "nothing in the codebase loads `src/content/templates/*.json`". That
is no longer true, and the block does not apply.** `src/services/range.ts` loads all nine template
files by static import and validates each through `templateSchema`, with a written note explaining
why a static import rather than a directory read (Metro has no filesystem on a device). A-009
shipped that, and its frozen tests exercise it.

T-019 is still worth having and is still `backlog`: it gives the same table an engine-side home
behind `templatesForSkill()` and adds the catalog-wide golden suite. When it lands,
`src/services/templatePools.ts` collapses into a re-export. **That is a follow-up, not a
precondition** — treating it as a blocker would idle the most checklist-critical ticket in the app
track behind a wave-6 engine ticket, three days from submission, for no reason.

## Acceptance Criteria

- **AC-1**: Given a skill and an rng, when a question is requested, then it is produced by the
  engine's `generateQuestion` over that skill's loaded template pool, and the returned
  `DuelQuestion.templateId` is the `id` of a template present in that pool.
- **AC-2**: Given the same seed, the same skill and the same recency list, when two questions are
  drawn, then they are identical in every field — the replay property survives the rewrite.
- **AC-3**: Given a recency list containing a template id, when a question is drawn for that skill,
  then the returned `templateId` is not among the first `RECENT_TEMPLATE_WINDOW` entries of that
  list, for as long as the pool has an alternative.
- **AC-4**: Given any generated question, when its choices are inspected, then there are exactly
  `CHOICE_COUNT` of them, `answer` appears exactly once among them, and no other choice equals the
  answer.
- **AC-5**: Given a duel that has asked several questions, when the reducer's state is inspected,
  then `recentTemplateIds` carries each drawn question's `templateId` most-recent-first and every
  entry is a real id from the loaded pool — the adapter delegates to `generateQuestion` and invents
  nothing of its own.

## Test Plan

- Unit (deterministic): AC-1 through AC-4, swept over every id in `SKILL_IDS` rather than a
  hand-picked skill — a pool that throws `NO_TEMPLATE` does so per skill, and the one skill nobody
  sampled is the one a child hits.
- Integration (deterministic): AC-5 driven through `duelReducer` — `PICK_CANNON` across two turns,
  asserting the window advanced and the ids are real.

      wording banned the literal string `a + b`; LESSONS L-016 records source-text bans as a
      measured failure mode in this repo, because a text ban does not know about syntax and its
      false-positive surface is every identifier and comment sharing a substring with it. The
      authoritative guard here is behavioural — AC-1 and AC-5, which a hand-rolled generator cannot
      satisfy because it has no `templateId` to report.
