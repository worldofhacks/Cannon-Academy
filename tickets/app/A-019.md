## Context

The Expo Router web export already builds and runs locally. The release need is a public,
extensionless-path-safe URL early, followed by a cheap redeploy after A-015. EAS Hosting is the
primary path because the Expo project is already linked and EAS handles Router static output.
Firebase Hosting is fallback one. Railway is not selected: this bundle is static and does not need
a server process.

## Acceptance Criteria

- **AC-1**: Given the current `app/shell` commit, when `npx expo export --platform web` runs, then it
  exits zero and emits all ten expected static routes under `dist/`.
- **AC-2**: Given the exported bundle, when it is deployed to EAS Hosting production, then the
  command returns a public HTTPS `*.expo.app` URL.
- **AC-3**: Given the production URL, when `/` and a cold direct request to `/chart` are loaded, then
  both return the app rather than an unmatched route, host error, or missing asset page.
- **AC-4**: Given the live app at a 375×812 viewport, when onboarding is completed or a seeded
  captain is resumed, then chart and duel render with no page or console errors.
- **AC-5**: Given the deployment, when release evidence is recorded, then it includes the URL,
  deployed commit, export output, deployment output, and live smoke results.

## Test Plan

- Build gate (deterministic): AC-1.
- Host probes (deterministic): AC-2 and AC-3 via deployment output and HTTP requests.
- Browser smoke (deterministic interaction): AC-4.
- Evidence audit (process): AC-5.

No implementation is planned. If EAS fails for a code/config reason, a separate fix ticket freezes a
reproducing check before an implementer edits hosting files. Account/network failures use the
handoff's ordered fallbacks without changing app code.

## Definition of Done

- [ ] Export gate passes from `app/shell`.
- [ ] Public production URL exists.
- [ ] Root and `/chart` deep link smoke tests pass.
- [ ] Live chart and duel smoke tests pass.
- [ ] `[process]` Orchestrator verified the deployed commit and evidence.

## Out of Scope

Native App Store/TestFlight distribution, backend APIs, Firebase Auth wiring, custom domains, and
Railway services.
