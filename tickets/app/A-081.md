## Ruling

Amended D-17 + `docs/ENDLESS-ARCHIPELAGO-DESIGN.md` §2 S3/S4. The sharpest bite in the wave:
with `currentIsland` parked at an authored island, an ungated settlement would mark the
ANCHOR island's authored ship met — a shelf lie.

## The work

1. **One additive option on `settleDuelRewards`**: `fleet?: 'mark' | 'hold'` (default
   `'mark'`), gating ONLY the metRivals block (`rewardSettlement.ts:274-279`), exactly as
   `voyage: 'hold'` gates advance (`:243-246`). No existing caller passes it — every frozen
   settlement behavior is unchanged, including the guided-duel call-site regex pin
   (`win-advance.test.ts:391-399`).
2. **`settleUnchartedDuel(store, core, doc)`** in `src/services/uncharted/settlement.ts`:
   delegates to `settleDuelRewards(store, core, { voyage: 'hold', fleet: 'hold' })` — coins,
   mastery tallies, receipts (`duel:gduel_…` rides the existing grammar), chest, rank all on
   the existing path — then, on a win, marks the ACTUALLY-FOUGHT rival honestly:
   `doc.rivalDocId` into `metRivals` (the same ids the shelf lights). The anchor island's
   authored enemy is NEVER marked.
3. **`advanceUncharted(store, seed)`**: explicit action, never a settlement side effect —
   guarded on a settled win for `uncharted.current`; increments clearedCount, promotes
   next→current, generates the new next via A-078. Idempotent per island (double-tap safe,
   the receipt-idempotency discipline).

## Acceptance criteria

- **AC-1**: A settled gen win pays coins + receipt + mastery exactly once (idempotent on
  replay of the same duelId) and `captain.currentIsland` / `unlockedIslands` /
  `chartProgress` are BYTE-unchanged before vs after — deep-equal proof.
- **AC-2**: `fleet:'hold'` — the anchor island's authored ship is NOT in `metRivals` after a
  gen settlement; `doc.rivalDocId` IS (win only; a loss marks nothing and advances nothing).
- **AC-3**: `advanceUncharted` moves the frontier exactly one island per settled win, is a
  no-op without one, and is NEVER called from inside settlement (source-scan on
  rewardSettlement.ts + the service).
- **AC-4**: The frozen `win-advance.test.ts` suite passes with only ADDITIVE specs — the
  chain-end pin (`:155-158`), the fixpoints, and the guided-duel regex are untouched. The
  default `fleet:'mark'` path is pinned so authored settlements behave exactly as today.

## Constraints

`rewardSettlement.ts` changes are the two-line gate + option plumbing ONLY — the receipted
commit structure, grant order, and every existing block stay byte-identical. If any existing
spec in `win-advance.test.ts` reddens, STOP and report; this ticket re-baselines nothing.
