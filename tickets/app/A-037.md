## Context

A-038 owns route wiring. This release-only ticket proves the complete path on native and
production rather than inferring it from headless tests.

## Planning Decisions

- **[locked-decision]** EAS Hosting remains web production. Firebase is the backend, not the static
  app host; Railway is unnecessary without a server.
- **[locked-decision]** Deploy first to a non-production immutable EAS deployment with the
  `production` environment, smoke it, then promote its exact deployment id with
  `eas deploy:alias --prod --id <id>`. Rollback re-promotes the preceding known-good immutable id;
  it never rebuilds under pressure.
- **[locked-decision]** Firebase rollback removes/reverts EAS public config to local-only and
  redeploys the preceding audited Firestore/Storage rules commit. It does not delete the permanent
  `nam5` database or `us-central1` bucket.

## Acceptance Criteria

- **AC-1**: Given A-038's route inventory, when release verification starts, then every production
  route has a real inbound edge and every exit lands on a valid route.
- **AC-2**: Given a fresh grade-band captain, when the scripted demo runs, then onboarding, guided
  duel, island-specific rival, victory chest, easier practice, cannon acquisition/equip, harbor
  spend, rank view, and relaunch all complete without hidden state injection.
- **AC-3**: Given insufficient coins and an offline Firebase client, when the demo reaches those
  states, then local play remains usable and the UI explains the limitation without a crash.
- **AC-4**: Given production deployment, when `/`, `/chart`, `/harbor`, `/rank`, `/range`, and
  `/duel` are cold-loaded, then they return the app and produce no runtime/worklet error.
- **AC-5**: Given final evidence, then it records exact commit, gates, test count, simulator/device,
  screenshots, PR status, production URLs, and Firebase service state.
- **AC-6**: Given the configured production build, when cold-launched twice, then anonymous Auth
  restores the same UID and an owner-only profile write/read succeeds; missing EAS variables,
  disabled provider, wrong project/app id, wrong database/bucket location, or failed rules test
  blocks promotion rather than being accepted as local-only.
- **AC-7**: Given the new immutable deployment or backend rules fail smoke, when rollback is
  rehearsed, then the prior EAS deployment id is promotable and the prior rules/config commands
  are recorded with their verification probes.
