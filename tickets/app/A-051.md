## Reported

> "there are still no green checks on the islands that get completed"
>
> "if you select the most basic level you should not have multiplication and division for those users
> it should be different based on the learning level"

Two bugs, one cause: the band gates what a child is **asked** in several places, and every place has to
remember to apply it. Two forgot.

## Bug 1 — the green check was unreachable, not merely absent

`chartNodes` measured `cleared` against **every** skill an island teaches:

```ts
cleared: island.rangeSkills.every((skill) => isMastered(...))
```

Port Sumwich teaches four — `add_within_10`, `add_within_20`, `sub_within_20`, `two_step_add_sub` —
and the last is **`minGrade: 2`**. A K–1 captain (`maxGrade: 1`) is never served it, because
`range.ts` refuses a drill above the band. So `every` could never be satisfied, and **their first
island could never earn its check however completely they finished it.**

Not a cosmetic miss: the tick was _unreachable_ for the youngest band, which is the band the whole
product is designed for. Fixed by measuring `cleared` against the in-band skills only — the same
filter `resolveUnlocks` already applies when deciding whether an island is eligible at a band at all,
so the two now agree on what "done with this island" means.

Guarded against the obvious over-correction: `[].every(...)` is `true`, so an island with nothing
age-appropriate to teach would tick for a K–1 child. `inBand.length > 0` prevents that, and a test
pins it.

## Bug 2 — × and ÷ on a kindergartner's gun deck

`app/gun-deck.tsx` drew a flat literal:

```ts
const OPERATIONS: readonly string[] = ['+', '−', '×', '÷'];
```

Lit for operations the captain owns a gun for, dulled for the rest — so a child who picked K–1 saw
multiplication and division on their own deck, presented as things they have not earned yet, three
years before the curriculum introduces them.

Everything else already gated correctly, which is why this was the only leak:

- `range.ts` filters drill skills by band and refuses one above it
- `rankView` filters its skill rows by band
- `resolveUnlocks` will not open an island whose range teaches nothing age-appropriate

Fixed by mapping each operator to the lowest `minGrade` among the catalog skills that use it, then
filtering by the captain's band. A K–1 deck now shows `+` and `−`.

## Acceptance criteria

- **AC-1**: If a band can be taught an island at all, mastering everything that band is offered there
  clears it. An island with nothing in band is not ticked by vacuous truth.
- **AC-2**: Mastering nothing clears nothing, at every band.
- **AC-3**: The gun deck's operator row is band-gated, and each operator's declared grade equals the
  lowest `minGrade` of a catalog skill using it — so the chip appears exactly when the curriculum
  does, rather than at a hand-picked number.

## Verification

`tsc` clean, eslint clean, 2,315 passing (6 new) with the same 16 pre-existing failures HEAD produces.

The new suite is verified non-vacuous: stashing both fixes and re-running turns 3 of its 6 red,
including a message that names the cause — _"port_sumwich is unclearable at k_1: mastered all 3
in-band skill(s) and it still did not tick."_

Note on the fixture: `isMastered` requires **both** a weighted total and an accuracy floor, so a
fixture setting only `weightedCorrect` fails the accuracy half and the test goes red for the wrong
reason. The helper sets `weightedCorrect`, `correct` and `attempts` together.
