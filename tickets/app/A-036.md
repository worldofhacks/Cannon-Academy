## Context

Current docs contain expired deadlines, stale test counts, a false “bot wired” claim, contradictory
Firebase status, and duplicated ticket tables. Several files already have uncommitted prior-session
edits, so reconciliation must preserve and review them rather than overwrite them from another
worktree.

## Planning Decisions

- **[locked-decision]** README/RELEASE describe deployed behavior; PLAN/ARCHITECTURE describe intent
  and target design; HANDOFF is a dated snapshot; STATE stays retired; COORDINATION is an interface
  contract; ticket status comes only from A-035.
- **[locked-decision]** Generated counts come from a fresh gate run and are never copied forward.
- **[locked-decision]** Firebase client config, provisioned services, and live sync are named as
  three separate states.
- **[locked-decision]** EAS Hosting is the canonical Expo web host already in production.
  Firebase supplies Auth/Firestore/Storage; older Firebase Hosting architecture text is corrected
  rather than creating a second web production target.

## Acceptance Criteria

- **AC-1**: Given every status-bearing document, when checked, then it links to `tickets/INDEX.md`
  and contains no competing live ticket count/table.
- **AC-2**: Given README and RELEASE, when compared with routes and production evidence, then every
  shipped/limited claim is accurate, including guided duel, bot, store, ranks, Firebase, hosting,
  and native verification.
- **AC-3**: Given PLAN and ARCHITECTURE, when a future/target feature is not shipped, then it is
  labeled intent rather than current implementation.
- **AC-4**: Given current test/build/deployment evidence, when documentation is updated, then counts,
  commit, PR, and live URL match the final verified artifacts.
- **AC-5**: Given Firebase setup, then docs explain public Expo env identifiers, local `.env`
  handling, EAS environments, Auth/Firestore rules, Storage's Blaze requirement, and the chosen
  Firestore location without exposing credentials.

## Test Plan

- Process review: compare final docs to fresh gates, Firebase CLI state, PR, and live smoke.
