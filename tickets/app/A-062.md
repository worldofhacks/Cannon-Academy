## Reported

> "we should remove the need to play the same island multiple times to move to the next ones so
> it does not feel repetitive."

Ruled as **D-11** (`tickets/app/OWNER-RULINGS.md`): winning a duel on an island immediately opens
the next band-eligible island in the chain. Mastery keeps paying cannons; the band gate is not
negotiable; the entry cannon still lands with its island.

## What is actually true

Fog lifts today only via `resolveUnlocks` (`src/engine/mastery.ts:128-193`): one predecessor
`rangeSkill` mastered — `MASTERY_THRESHOLD_CORRECT = 10` at `MASTERY_MIN_ACCURACY = 0.7`
(`src/engine/tuning.ts:169-172`) — which is 2–3 wins on the same island. The dock meter derives
`duelsToOpen` from answers-to-mastery arithmetic (`src/services/chart.ts:154-162, 214-219`,
rendered `NEXT: ${n} DUELS` at `Dock.tsx:196`). There is no wins-per-island counter anywhere;
settlement records the win (`rewardSettlement.ts:245`) and moves on.

Two safety properties are load-bearing and must survive:

- **Band eligibility** (`mastery.ts:144-152`): an island opens only if it teaches something at or
  under `maxGradeForBand`. A naive next-in-chain unlock sails a K-1 captain into Quotient Cove's
  division — the exact failure A-060 exists to prevent, tripwired at
  `k1-island-progression.test.ts:236`.
- **Entry-cannon grant** (`mastery.ts:181-190`): a newly opened island grants exactly one in-band
  entry cannon, or the captain arrives with no gun that asks the island's questions (the
  circular-acquisition bug this code exists to fix).

Also folded in here because these files are already open: **six engine tests are red on main**,
stale against the owner's 2026-07-30 `MASTERY_RATE_DUEL` 0.5→1 change —
`mastery.test.ts` `spec(T-010:AC-2)` (:182) and `spec(T-010:AC-5)` ×3 (:229, :235, :257), plus
`tuning.test.ts` :310 and the rate-relationship case (:317-341). `tuning.ts:189-191` claims the
re-baseline happened; it did not.

## Fix

- New engine helper (exported from `src/engine/mastery.ts`, pure): `advanceOnWin(islandId, band,
  unlockedIslands, unlockedCannons)` → `{ islands, cannons }` — the next island in the chain whose
  `requiresIsland` is the won island, filtered through the **same** band-eligibility rule
  `resolveUnlocks` uses, with the entry-cannon grant extracted and reused so both paths pay the
  arrival gun identically.
- `settleDuelRewards` (`rewardSettlement.ts`, after `recordWin`): when `won`, apply
  `advanceOnWin` inside the same idempotent receipted commit — one `replaceCaptain`, replay-safe
  under the existing `duel:<id>` receipt guard.
- `chartProgress` (`services/chart.ts`): `duelsToOpen` becomes wins-based — `1` whenever a next
  band-eligible island exists — keeping the caption plumbing so `Dock.tsx` reads `NEXT: 1 DUEL`,
  and the fully-open-at-ceiling state keeps its existing complete/hidden copy.
- Re-baseline the frozen specs D-11 invalidates, citing D-11 in each test header; fix the six
  stale rate tests citing the 2026-07-30 ruling.

## Acceptance criteria

- **AC-1**: Winning one duel on an island opens the next band-eligible island immediately —
  driven through the real path (`commitGradeBand` → duel → `settleDuelRewards`), asserted at
  every band. A K-1 captain who wins once on Port Sumwich holds Isla Products.
- **AC-2**: The band gate holds under instant advancement: a K-1 captain's reachable set is
  exactly `[port_sumwich, isla_products]` no matter how many wins — the A-060 fixpoint preserved
  for the right reason, and its tripwire test stays.
- **AC-3**: The entry cannon lands with its island (Grapeshot arrives with Isla Products),
  exactly once, and settlement replay of the same `duelId` grants nothing twice.
- **AC-4**: Only wins advance: a lost duel and a range drill lift no fog; mastery-driven cannon
  unlocks through `resolveUnlocks` are unchanged (existing cannon specs stay green untouched).
- **AC-5**: The dock meter tells the truth: `NEXT: 1 DUEL` while a next island exists; the
  voyage-complete state unchanged. No caption dead-ends at any band.
- **AC-6**: The suite is honest again: the six stale rate tests are re-baselined against
  `MASTERY_RATE_DUEL = 1` with the ruling cited, and `engine/mastery` + `engine/tuning` suites
  pass entirely.

## Constraints

- Route island opening through the band-eligibility filter — never a bare next-in-chain unlock.
- Re-baseline `k1-island-progression.test.ts` specs that pin mastery-gated fog (:195, :217-222)

- Touch nothing in `stores/duel.ts` or `app/duel.tsx` (A-063 owns the chart screen; the duel
  screen is out of scope — settlement is the seam).
- `spec(A-008:AC-3)` crossing-grant behaviour in `duel-outcome.test.ts` is baseline-red already;
  do not chase it, do not worsen it.
