## Reported

> "We can generate new ships within a specific zod schema since they are svgs, we should use the
> existing upgrade options we have as golden examples, and then generate 20 more so we have solid
> golden set to generate off of."

Ruled as **D-12** (`tickets/app/OWNER-RULINGS.md`): generated ships may ship as data when every
field is an enum or count over board-sanctioned primitives. The schema is the provenance
boundary; A-045's regime is otherwise unchanged.

## What is actually true

Ship *colors* are already pure data — `ShipSkin` (`shipSkins.ts:42-60`) maps onto the hull via
`shipCosmeticsForCaptain` with zero component changes. Ship *shape* is not: hull, sails and
pennant are string-literal outlines and numeric anchors in a 150-unit grid inside `Ship.tsx`
(`:91-126, 225-258, 403-421`), whose source text is **pinned by frozen tests** —
`sprites.test.ts` `spec(A-045:AC-2/AC-3)` (:150-207) reads `Ship.tsx` directly. The emblem parts
a schema needs (crossbones, skull) already exist as composed geometry (`Ship.tsx:534-628`), and
`Poly` (`Poly.tsx:32-38`) is an SVG polygon on a 0–100 viewBox — a document of enums over these
parts is renderable by construction.

Hard walls, all frozen:

- `ShipSkin`'s key set and its 4-entry catalog are pinned (`ship-skins.test.ts:50, 96-111`) —
  generated ships **cannot** extend them; they need their own catalog.
- The island→presentationKind mapping and the 5 shape channels are pinned
  (`enemy-presentation.test.ts:85-101`) — generated docs must not replace rivals here.
- Any new PNG in `assets/sprites` fails `spec(A-045:AC-1)` (:98-112) — vector documents only.
- The red vertical sail stripe is the player's alone (`enemyPresentation.ts:30-32`).

## Fix

- **Schema** (`src/content/generatedFleet.ts`, strict like every catalog schema):
  `generatedShipSchema` = id (`gen_ship_*` regex), displayName (≤24 chars, child-appropriate),
  role `rival|showcase`, palette as a strict object whose every value is `z.enum` over named
  token swatches (never free hex), hull `{strakes 1-3, gunports 0-3, sternCastle}`, 1–3 sails
  `{slot, shape clean|tattered, stripe none|band}` with unique slots (`vertical` stripe only
  representable when role is not `rival`), flag `{shape, emblem none|crossbones|skull|star|fish}`.
  **No coordinate fields anywhere.**
- **Renderer** (`src/components/duel/GeneratedShip.tsx`, a NEW file — `Ship.tsx` is never
  edited): consumes one valid document; reuses `Poly` and lifted sail/emblem geometry on the same
  150-grid with fixed anchor points; varies only what the schema varies.
- **Goldens** (`src/content/generatedFleet.json`): ~35 candidates authored against the schema,
  culled by eyeball to exactly **20**, validated at import via `parseCatalog` exactly like
  `enemies.json`.
- **Preview grid** (`scripts/fleet-preview.ts`, run with `node` — this machine's Node 25 strips
  types natively): renders every golden as plain `<svg>` into one static HTML page at
  `design/generated-fleet/preview.html`, committed so the fleet is reviewable in a browser with
  no Expo running.

## Acceptance criteria

- **AC-1**: The schema is closed: strict parse; free hex unrepresentable; duplicate sail slots
  rejected; a `vertical` stripe on a `rival`-role document rejected; ids constrained to
  `gen_ship_*`; no field can carry raw coordinates.
- **AC-2**: Any valid document renders: `GeneratedShip` draws every golden without throwing
  (rendered through the same test harness pattern the repo uses for composed geometry), and
  `Ship.tsx` is byte-identical to before this ticket.
- **AC-3**: Exactly 20 goldens ship: all strict-parse, unique ids, no two documents identical,
  every displayName reviewed as child-appropriate, catalog validated at import.
- **AC-4**: The preview grid regenerates: running `scripts/fleet-preview.ts` reproduces
  `design/generated-fleet/preview.html` from the committed goldens byte-for-byte, and the page
  shows all 20 with ids and names.
- **AC-5**: No frozen surface moved: `sprites.test.ts`, `ship-skins.test.ts`, and
  `enemy-presentation.test.ts` pass untouched; no new raster exists anywhere in the repo; no
  captain field was added.

## Constraints

- `Ship.tsx` is read-only reference material — lift geometry by copying into the new renderer,
  never by editing or re-exporting from it.
- Palette enums must be drawn from `src/theme/tokens.ts` named values; document which swatches
  are in the curated list and why (contrast-audited ramps only).
- Generated ships are not ownable, not purchasable, and carry no engine meaning — paint and
  silhouette only, mirroring the A-052 shape lock.
- displayNames face five-year-olds: playful-menacing is fine ("Bone Brigade"), realistic menace
  is not.
