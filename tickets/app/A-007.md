## Context

**This is the missing hub.** `islands.json` ships five islands with unlock chains and requirement
edges, and nothing renders them. Without the chart there is no loop — only a duel you can replay,
which is exactly what the current build is.

Every other screen routes through here: onboarding ends here, duels start and end here, the range
hangs off an island node.

## Acceptance Criteria

- **AC-1**: Given a captain's unlocked islands, when the chart renders, then exactly those islands
  are enterable and the rest are fogged.
- **AC-2**: Given an island whose `requiresIsland` is not yet cleared, when the chart renders, then
  it is fogged regardless of grade band.
- **AC-3**: Given a fogged island, when it is tapped, then nothing navigates and the requirement is
  stated in words a child can read.
- **AC-4**: Given the captain's current island, when the chart renders, then their ship is drawn at
  that node.
- **AC-5**: Given a returning captain, when the app cold-starts, then the chart is the first
  interactive screen and it reflects persisted progress.
- **AC-6**: Given a 360×640 screen, when the chart renders, then all five nodes are reachable
  without clipping.

## Test Plan

- Unit (deterministic): AC-1, AC-2, AC-5 — fog and reachability are pure functions of captain
  state plus the island catalog, and belong in a testable selector rather than in the component.

- Visual (design-fidelity, NOT frozen): verified against the named board at the 375pt reference
  width, and at 360×640 / 390×844 / 430×932. Recorded as a screenshot diff in the ticket, reviewed
  by a second agent. **This is a posture-gated deferral**: the app layer has no component-test
  harness, so screen geometry cannot be frozen-tested today (see `.tdd-swarm/posture.md`).
