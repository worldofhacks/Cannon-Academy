## Context

The hydration splash is the designed first frame, but a fast local read removes it before a person
can see or record it. A clean install therefore appears to start on “Which ship is yours?”, even
though board 4a exists. The latest owner instruction explicitly overrides `HANDOFF.md` §7's older
“no title screen” demo order: the branded Cannon Academy screen must remain until the presenter
starts the flow.

The iPhone 17 Pro simulator also proves that every sample problem on board 1a is vertically clipped.
The current problem line height equals its font size, which cuts the Baloo 2 ascenders. This is a
rendered defect; accessibility text and unit tests still see the complete strings.

## Planning Decisions

- **[locked-decision]** The existing board-4a splash becomes a two-state launch gate. While fonts
  or local hydration are pending it keeps the non-interactive three-lamp loader. Once both settle,
  it replaces the loader with one `SET SAIL` button and remains visible until that button is
  pressed.
- **[locked-decision]** Pressing `SET SAIL` routes to the one destination already returned by
  `resolveDestination`; the launch gate never inspects captain fields or invents a route.
- **[locked-decision]** A pure `createLaunchGate` controller captures that destination and owns a
  synchronous one-shot latch. Repeated presses before React rerenders cannot navigate twice, and
  tests exercise this controller directly instead of inferring behavior from regex alone.
- **[locked-decision]** This is not a credential form. Firebase anonymous sign-in remains A-026;
  the launch gate must not claim a UID exists or block local play on Firebase.
- **[locked-decision]** A full JS/native relaunch resets the in-memory launch acknowledgement so
  every recording take begins on board 4a. In-app navigation does not show it again.
- **[locked-decision]** Picker copy remains board 1a's exact wording. Fit is fixed with sufficient
  line boxes and bounded single-line scaling, not by shortening or hiding the math/grade labels.

## Acceptance Criteria

- **AC-1**: Given fonts or hydration are pending, when the root renders, then board 4a is visible,
  its three-lamp loading treatment is visible, and no start control can fire.
- **AC-2**: Given fonts and hydration have completed, when no start acknowledgement exists in the
  current app process, then board 4a remains visible with exactly one accessible `SET SAIL`
  control and no navigation has occurred.
- **AC-3**: Given the ready launch gate, when `SET SAIL` is pressed, then the root navigates exactly
  once to the previously resolved destination; it does not branch on captain fields.
- **AC-4**: Given a fresh process after a prior play session, when the app launches, then the launch
  acknowledgement starts false again while persisted captain progress still resolves normally.
- **AC-5**: Given every board-1a problem and band label at release widths, when rendered, then the
  complete strings remain single-line, have bounded shrink behavior, and the problem line box is
  taller than its font size so Baloo 2 glyphs are not vertically clipped.

## Test Plan

- Unit/source contract (deterministic): freeze root launch-state transitions, resolver-only
  navigation, ready/loading control exclusivity, and the picker text-fit props/line-box invariant.
- Visual release evidence (required): inspect board 4a followed by board 1a on the iPhone simulator,
  and inspect board 1a at 360×640 and 375×812 web viewports. All three problem strings and band
  labels must be visibly complete.
