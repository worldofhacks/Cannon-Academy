## Source of truth

Board: `Cannon Academy Rival Fleet.dc.html`, section **3c — Deck crew construction reference**,
in Claude Design project `88888c12-22e4-4781-b76f-a28110506499` (read it in full first; design
MCP read tool via ToolSearch). Three reference figures — Bosun, Gunner, Powder monkey — with
exact shape recipes, and two red-card rules that are law: **no skull on a crew face**, and
**no rival ever carries the red-and-white striped sail** (not this ticket's surface, but the
same uniqueness logic: the player's captain figure stays visually theirs).

## What this is

Rival decks are empty today — only the player's ship carries a figure. This ticket puts exactly
one chibi sailor on the rival's deck in a real duel, chosen deterministically from the duel's
fleet variant so a rematch shows the same sailor.

## Construction rules (from 3c, binding)

- 34×54 grid, same body plan as the player captain: two boots, coat block with hem shade, two
  sleeve arms with hand dots, head circle, hat bar. Nine to eleven shapes total.
- Accessories are drawn ON existing shapes, never added as new ones: eyepatch = one band across
  the head circle (+ enlarged dark eye), hook = grey J replacing a hand dot, beard = rounded
  block under the face, earring = 4px gold dot on the head's edge. **Maximum two per figure.**
- Coats from the board's crew palette (`#B02418`, `#1E7F41`, `#1E5A8A` + the existing four
  captain swatches where reused); skins from the three board skin tones. Named token additions
  with board citation for any hex not already in tokens.ts.
- Never a skull face; the skeleton KIND reads through its ship, not a corpse sailor.

## Acceptance criteria

- **AC-1**: `GeneratedPirate` renders any crew document (coat, skin, hat kind, ≤2 accessories)
  within the shape budget; the crew document derivation is a pure exported function
  (`crewFor(variantId)` in `crewPresentation.ts`) the tests drive: deterministic per variant,
  accessories never exceed two, skull unrepresentable by construction.
- **AC-2**: In a real duel the rival deck shows exactly one sailor derived from
  `rivalVariantFor(islandId, duelId)` (A-067's service); the player's deck is unchanged; a
  rematch of the same duelId shows the same sailor.
- **AC-3**: `Ship.tsx` is byte-identical — the sailor mounts through `SeaStage`'s composition
  layer (the sprites-suite pins must pass untouched).
- **AC-4**: Kind exceptions hold: the kraken fields no sailor (no deck — its cosmetics are
  null by frozen contract); the ghost's sailor renders inside the ghost's opacity treatment.

## Constraints

- Only the three files in scope. `Ship.tsx`, `app/duel.tsx`, `enemyPresentation.ts` are
  read-only reference.
- If `rivalVariantFor` has not landed when you start (A-067 runs just ahead of you), build
  against its documented signature `rivalVariantFor(islandId: IslandId, duelId: string)` and
  integrate when it appears — your suite may stub it, but the source-guard AC-2 wiring pin
  must reference the real import.
