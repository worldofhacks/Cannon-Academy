## Context

`zustand` is not installed, `AsyncStorage` appears only in comments, and `firebase` is a dependency
no file imports. The duel resets on every mount, `computeCoinPayout` returns a number that is
immediately discarded, and onboarding pushes into a duel that does not know which grade band was
chosen.

**Every other ticket in this set is downstream of this one.** It is not a screen — it is the reason
screens can mean anything to each other. The shape mirrors the Firestore captain document in
ARCHITECTURE.md §5 so the later sync ticket is a write, not a translation.

## Acceptance Criteria

- **AC-1**: Given a fresh install, when the store initialises, then every field holds a well-formed
  empty value — never `undefined`, never a missing key.
- **AC-2**: Given any sequence of exposed actions, when they are applied, then `coins` is never
  negative.
- **AC-3**: Given a captain with mastery below threshold on a skill, when `recordDuelAnswers` is
  called with correct answers, then the matching skill's meter rises at the duel rate from
  `MASTERY_RATE_DUEL` — the store never computes its own rate.
- **AC-4**: Given a mastery meter crossing `MASTERY_THRESHOLD_CORRECT` at or above
  `MASTERY_MIN_ACCURACY`, when the crossing is recorded, then the unlock returned by the engine's
  mastery module is applied to `ownedCannons` exactly once, and re-applying is a no-op.
- **AC-5**: Given a completed duel, when the result is recorded, then `wins` increases only on a
  win and `rankTier` is derived by `rankTierForWins` — never assigned directly.
- **AC-6**: Given a loss, when the result is recorded, then `rankTier` does not decrease.
- **AC-7**: Given the store module, when it is imported, then it imports nothing from `app/**` or
  `src/components/**`.

## Test Plan

- Unit (deterministic): every AC above. The store is pure TypeScript over engine functions and runs
  headless under the existing vitest node environment — no component harness required.
- Property (deterministic): a random action sequence never produces negative coins, a decreased
  rank tier, or a duplicated cannon in `ownedCannons`.
