## Reported

> "one of the cannons did not work at all and after a few turns it returned this error: Rendered
> fewer hooks than expected. This may be caused by an accidental early return statement.
> app/guided-duel.tsx (55:7)"

Two separate defects, both reproduced and both fixed.

## Defect 1 — the hook-order crash

`GuidedDuelBody` called `useCallback`, `useCallback` and `useEffect` (lines 146, 161, 168) **below**
`if (captain.hasFoughtGuidedDuel) return <Redirect href="/chart" />` (line 139).

The trigger is not exotic — it is the win condition. `settleGuidedDuel` sets
`hasFoughtGuidedDuel = true` on victory; the `captainStore` subscription re-renders the component;
the redirect now fires; three hooks disappear; React throws. **The one duel every child is
guaranteed to play crashed on the turn they won it.**

`app/duel.tsx` had the same shape and was worse: **eight** hooks below
`if (!duelContext.ok) return <Redirect href="/chart" />` at line 106.

**Fix:** every hook now runs before any conditional return on both routes. `cannon` and `look` moved
down with the redirects — they derive from `fallback` and are read only by JSX, never by a hook.

### Why nothing caught it

`react-hooks/rules-of-hooks` **does not flag this shape.** It catches a hook inside an `if`, a loop
or a callback; a top-level hook that merely sits _after_ an `if (…) return` is invisible to it.
eslint was clean on both files the day the crash shipped, and so were 2,307 tests — tests do not
traverse the router, and this only fires on a real state transition.

So `__tests__/app/hook-order.test.ts` is a static scanner over every `.tsx` in `app/` and
`src/components/`. It is verified non-vacuous two ways: it flags the exact pre-fix source (three
violations at the real line numbers, confirmed by stashing the fix and re-running), and it clears the
post-fix shape.

## Defect 2 — the dead cannon

`guidedConfig` sets `playerLoadout: ['swivel_gun']`. The engine's `selectCannon` returns **the same
state, silently**, for any id outside that list:

```ts
if (!state.playerLoadout.includes(cannonId)) {
  return state;
}
```

But the screen rendered `trayCannons(captain)` — the captain's whole equipped set, which for a fresh
K-1 captain is Swivel Gun **and** Culverin. So the Culverin tile was live, tappable, and inert. No
error, no feedback. A dead button in the one duel whose entire job is teaching a five-year-old that
tapping a cannon does something.

**The board settles which side is wrong.** The corrections board's _Guided first duel_ screen draws
exactly one cannon and says: "Tap the green cannon", "One spotlit target… Everything else dims to
35%", "The tutorial never blocks a tap". The engine config is right; the screen was wrong.

**Fix:** the guided tray is derived from the session's own `playerLoadout`, with a fallback to the
captain's tray if a future config and the catalog ever disagree — an empty tray would trip the
`/gun-deck` redirect and bounce a child out of onboarding.

## Acceptance criteria

- **AC-1**: No component in `app/` or `src/components/` calls a hook below an early return.
- **AC-2**: The guided duel renders only cannons its engine session will accept.
- **AC-3**: A guided duel can be played to victory without a crash.

## Verification

`tsc` clean, eslint clean, full suite 2,309 passing (2 new) with the same 16 pre-existing failures
HEAD produces.

**Played on screen at 375×667**, which is the only proof that counts here: fresh captain → K-1 →
skip name → guided duel shows **one** cannon → three volleys (rival 28 → 17 → 6 → 0) → victory
settled → redirected to the sea chart with 90 coins. **Zero console errors.** The chart ship also
renders correctly on arrival (`ship-01.png`, 66×113 natural at 41pt).

## Not fixed, deliberately

The board's guided duel also specifies a pointing hand, a spotlight dimming everything else to 35%,
"Nothing here can hurt you", and a "STEP 1 OF 3" counter. None of that is implemented. It is
tutorial polish, not a defect, and it is out of scope for a crash fix — but it is the gap between
this screen and its board.
