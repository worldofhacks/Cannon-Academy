## Reported

> "on the footer in the sea chart view there is out of bounds with the new options and they are
> compressed and unreadable"

Confirmed: the dock read `Har…`, `Rank`, `◎ P…`, `▬ G…`, `⚔ Fi…`, with the last button clipped off
the right edge.

## Cause — the arithmetic

The board's dock carries **two** wide buttons. A-038 put **five** in that row for demo reachability
and never re-laid it out.

- Inner width at 375pt: `375 − 2 × 12 inset = 351`
- Five controls at the 64pt tap-target floor: `5 × 64.5 = 322.5`
- Row was drawn with `DOCK.gap` (10): `322.5 + 4 × 10 = 362.5` → **overflows 351 by 11.5pt**

`flow.ts` had already solved this: `chartHubControlLayout` derives `gap = (351 − 322.5) / 4 = 7.125`,
which fits exactly. `Dock.tsx` ignored that and used `DOCK.gap` — two owners for one number,
disagreeing by ~2.9pt five times over.

It compounded: each button also had `flex: 1` **and** `minWidth: control.width`. `minWidth` stops
flex from shrinking anything, so the row could not absorb the overflow. And the icon sat _beside_ the
label, which needs far more than 64pt — hence the truncation independent of the overflow.

## Fix

- Fixed-size squares at `control.width` / `control.height` — the geometry `flow.ts` computed. No
  `flex`, no `minWidth` fighting it.
- The gap is read back off the controls' own `x` positions (`controlGap`), so the layout owner and
  its consumer cannot drift again.
- Icon **above** label instead of beside it, label at `DOCK.controlLabelSize` (10.5) with
  `adjustsFontSizeToFit`. All five now read in full.
- `harbor` and `rank` had **no icon branch at all** — they were relying on the label alone. Added
  `CoinStackMark` (three stacked coins) and `LadderMark` (three ascending bars), drawn from Views for
  the same reason `CannonMark` is: every glyph that reads as "coins" or "ladder" is emoji-capable, and
  an emoji ignores `color` on iOS.

### Labels were kept deliberately

The first attempt went icon-only, on the grounds that the board says "The board draws icons, not
words, in these slots". That **broke a frozen A-038 assertion** — `pressDispatchesEdge`'s
`hasVisibleLabel` requires a `<Text>` carrying `control.label` inside each Pressable, so a demo
viewer can see where every button goes. The test was right and the change was wrong; stacking the
label was the fix that satisfies both. No frozen test was weakened.

`DOCK.controlLabelSize` is flagged in `board.ts` as the one value in that file which is **not** a
board measurement, with the note to delete it if the dock ever returns to the board's two controls.

- **AC-2**: Every control shows its full label, untruncated.
- **AC-3**: Every control has a visible icon.
- **AC-4**: No frozen test is modified.
