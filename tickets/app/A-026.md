## Context

A-004 supplies a tested injected Auth seam but nothing invokes it. This ticket wires only the
session lifecycle. A-040 deliberately owns profile mapping, writes, and Firestore rules after the
gameplay persistence fields settle.

## Planning Decisions

- **[locked-decision]** AsyncStorage remains authoritative during play. Firebase identity and writes
  start after local hydration and never block the route resolver.
- **[locked-decision]** The observer is subscribed before anonymous sign-in is requested so a
  restored persisted user wins the race. At most one sign-in request may be in flight.
- **[locked-decision]** This boundary exposes `configured`, `local-only`, `connecting`, and
  `authenticated` states but never logs a UID or configuration value.

## Acceptance Criteria

- **AC-1**: Given a configured native client with a persisted anonymous user, when the app launches
  twice, then the Auth observer restores the same UID and does not create a second anonymous user.
- **AC-2**: Given missing config, offline Auth, or a rejected sign-in, when local hydration
  completes, then normal routing and local persistence continue in `local-only` mode.
- **AC-3**: Given observer and sign-in promises resolving in either order, when the session starts,
  then exactly one authenticated UID is retained and no second anonymous account is requested.
- **AC-4**: Given the root layout, then Firebase work starts after local hydration without
  extending the splash gate, starts exactly once, and unsubscribes on unmount.
- **AC-5**: Given a configured release client, when cold-launched and relaunched, then CLI/native
  evidence records the same anonymous UID without printing the UID itself.

## Test Plan

- Unit (deterministic): observer/sign-in order, duplicate-start protection, state transitions,
  cleanup, missing config, and non-blocking failures.
- Integration evidence: record one anonymous session surviving a native cold launch without
  exposing the identifier.

## Definition of Done

- [ ] Tests are RED, independently reviewed, and frozen before implementation.
- [ ] Anonymous Auth is enabled and verified against the exact Firebase project.
- [ ] No remote error blocks local play.
- [ ] Local gates, code review, and Security Agent review pass.

## Out of Scope

Firestore mapping/writes/rules, public leaderboard, account linking, analytics, and Storage upload.
