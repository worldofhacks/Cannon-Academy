## Source of truth

Board: `Cannon Academy Rival Fleet.dc.html` in Claude Design project
`88888c12-22e4-4781-b76f-a28110506499` — read it in full first (design MCP read tool via
ToolSearch). Section 3a is the shelf screen, 3b is the exact 20-row parameter roster (`FLEET`
in its data script — names, kind, strakes, ports, sails, castle, emblem), 3c is crew reference
(A-068's, not yours). The roster **supersedes** A-064's authored goldens: the catalog is
rebuilt to exactly those 20 rows.

## The pieces

1. **Catalog rebuild** — `generatedFleet.json` becomes the board's 20 ships verbatim (Bone
   Biscuit … The Last Grumble, plus the 20th `???` row which is real data that renders locked
   until met). Schema gains `kind: pirate|skeleton|ghost|shark|kraken`; per-kind hull/sail/mast
   palettes from the board's `HULLS`/`SAIL_FILL` tables enter tokens.ts as named additions
   (board citation); tattered-when-strakes≥3, castle, emblem, sail-count rules per the board's
   `build()`. D-12's walls stand: no free hex in documents, no coordinates, the player's
   red-striped sail unrepresentable on any rival.
2. **The shelf screen** — `app/fleet.tsx` per 3a: header exactly the Rank screen's pattern
   (44pt back chevron, `Rival Fleet` title, coin pill); `N OF 20 MET` from
   `captain.metRivals` (field already exists — do not touch store/persistence); the kind
   legend on its own wrapped line (color chip + word, never color-only); a scrolling 2-column
   grid of 152pt static cards — met = full ship render on sea plate + name + kind badge;
   unmet = grey silhouette, cream `?` disc, `Not met yet`, no badge ink contrast loss. No
   animation loops anywhere on this screen.
3. **Met, honestly** — `src/services/rivalVariant.ts`: `rivalVariantFor(islandId, duelId)`
   deterministically picks a fleet ship whose `kind` matches the island's `presentationKind`
   (seeded off the duelId, stable for replay). The duel's rival ship renders that variant's
   palette (hull/sail/flag emblem) — additively, WITHOUT disturbing the frozen
   enemy-presentation pins (island→kind mapping, five distinct shape channels, ghost opacity,
   kraken-has-no-cosmetics: kraken duels simply mark the kraken fleet entries met without a
   hull repaint). `settleDuelRewards` unions the variant id into `captain.metRivals` inside
   the same receipted commit, win or lose, idempotent per duel.
4. **The route** — expo-router `app/fleet.tsx`; `flow.ts` gains `fleet` in `DemoRoute` with
   edges `rank→fleet` (push) and `fleet→rank` (back); `demo-navigation`'s frozen
   `ROUTE_FILES`/edge inventory re-baselined citing this ticket (its own amendment protocol);
   Rank gains a parchment entry row — `Rival Fleet` / `The captains you've met.` — above
   Captain's Papers, 64pt target, matching the Papers rows' construction.

## Acceptance criteria

- **AC-1**: The shipped catalog is the board roster exactly — 20 documents, names byte-equal,
  every parameter column matching 3b's table — strict-parsed at import, and the rebuilt
  preview.html regenerates byte-for-byte via `node scripts/fleet-preview.ts` showing all 20.
- **AC-2**: The shelf renders both card states per 3a's geometry, the legend never renders
  color-only, and the MET count equals `metRivals ∩ catalog`. Screen behavioral logic
  (met/unmet projection, count) lives in a pure exported function the test drives directly.
- **AC-3**: Variant determinism: the same duelId always yields the same variant; every variant
  a duel can pick has the island's kind; across the five islands every catalog ship except
  `???`-class entries is reachable. Settlement replay of one duelId marks exactly one ship met
  exactly once.
- **AC-4**: The frozen surfaces hold: sprites, ship-skins, and enemy-presentation suites pass
  untouched; `Ship.tsx` byte-identical; the A-064 suite is re-baselined to the new catalog
  citing this ticket in its header (D-12 checks — hex/slot/stripe rejections — all preserved).
- **AC-5**: Navigation: fleet row visible on Rank, pushes the fleet screen, back returns;
  `demo-navigation` green after its sanctioned re-baseline; every dead end has an exit (the
  screen is reachable and leavable at SE and Pro Max).
