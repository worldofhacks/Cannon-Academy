## Context

The splash (board 4a) already exists and already holds the first frame. It currently waits only on
fonts. This ticket gives it the thing it is actually meant to wait for.

The failure this must prevent is specific and silent: an ungated redirect fires against empty state,
so a returning captain is shown onboarding and their progress appears erased. The README lists it
under traps already identified.

## Acceptance Criteria

- **AC-1**: Given a persisted captain, when the app relaunches, then every field round-trips to the
  exact value written.
- **AC-2**: Given no persisted data, when rehydration runs, then it completes and reports hydrated
  with the empty captain — it does not hang and does not throw.
- **AC-3**: Given a truncated or non-JSON payload in storage, when rehydration runs, then it
  resolves to the empty captain and reports the corruption — a child is never locked out of the app
  by a bad write.
- **AC-4**: Given a payload written by an older schema version, when rehydration runs, then it is
  migrated forward or discarded explicitly; it is never partially applied.
- **AC-5**: Given any storage — populated, empty, or corrupt — when `hydrate` is called, then the
  returned promise settles exactly once with a `HydrateResult` and never rejects, so a caller can
  use "the promise has settled" as its hydration gate and has nothing else to poll.
- **AC-6**: Given a write, when it fails (quota, permission), then the in-memory captain is
  unaffected and play continues.

## Test Plan

- Unit (deterministic): every AC, with AsyncStorage faked at the module boundary. This is I/O
  sequencing, not UI, and runs headless today.
- Integration (deterministic): store + persistence together — write, drop the module, rehydrate,
  assert equality.

## Planning Decisions

- **`hasHydrated` does not exist, and AC-5 no longer claims it does.** The README's trap note and
  ARCHITECTURE §8 both name a `hasHydrated` flag; nothing in the codebase exports one. The gate is
  real but is spelled differently: `app/_layout.tsx` holds `destination: Destination | null` and
  renders `<Splash/>` while it is `null`, so the first frame is held until `await hydrate(...)`
  lands and `resolveDestination` runs. AC-5 above is restated against the contract `hydrate`
  actually offers. **The layout-side half of the gate — that no redirect fires before the read —
  belongs to A-005 and is unasserted today**; it is screen wiring under the posture deferral, and
  it is recorded here so the gap is visible rather than implied.
- **Open coverage gap:** AC-5 as restated has no tagged assertion yet. It is a one-line addition to
  `__tests__/app/persistence.test.ts` and spec-lint stays RED on A-002 until it lands.
