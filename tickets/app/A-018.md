## Context

The rebuilt sea chart landed in `543a155` and introduced four Reanimated animations. It has never
been seen rendered on web or device. Two earlier launch-blocking failures survived more than 1,800
green tests; one was a JavaScript helper called from inside a `useAnimatedStyle` worklet. This is a
retrospective release-verification ticket: shipped behavior is being specified and observed before
the first production deployment. No implementation is dispatched unless an acceptance check fails.

## Acceptance Criteria

- **AC-1**: Given every `useAnimatedStyle` callback under `src/components/chart/`, when its body is
  inspected, then it calls no JavaScript closure or helper; layout/helper calls are precomputed on
  the JavaScript thread.

## Required Release Evidence

These checks remain mandatory, but are not numbered frozen-test criteria: the app layer has no
component/e2e harness and A-007 already records real-layout checks as a posture-gated screenshot
surface. Keeping them numbered would make spec-lint permanently red for work only a browser or
device can observe.

- At a 375×812 web viewport with a captain routed to `/chart`, the rebuilt chart, current ship, five
  stations, fog, coin pill, Fight, Practice, and Cannons controls are visible with no console or
  page errors.
- In the iOS development client synced to `app/shell`, the same captain reaches the chart and its
  first animated frame renders without a red screen or worklet exception.
- On web and iOS, Fight opens the duel, Practice opens the range, Cannons opens the gun deck, and
  back navigation returns to chart.
- Timestamped screenshots, runtime results, and the exact tested commit are stored under
  `.tdd-swarm/release-evidence/A-018/`.

## Test Plan

- Static regression (deterministic, frozen): AC-1. A Test Agent authors a source-structure check
  against all chart `useAnimatedStyle` callbacks. Because this specifies already-shipped code, it
  may be green on its first run; any production fix still requires a separate RED fix ticket.
- Browser smoke (deterministic interaction, release evidence): required web rendering and routing
  evidence above.
- iOS simulator smoke (device-only release evidence): required native rendering and routing
  evidence above.
- Evidence audit (process): screenshot, runtime result, and exact commit.

## Definition of Done

- [ ] `[process]` All four chart worklets have independent static-review evidence.
- [ ] `[process]` The frozen worklet regression test passes.
- [ ] `[process]` Web chart screenshot and console/error result are recorded.
- [ ] `[process]` iOS chart screenshot and native runtime result are recorded.
- [ ] `[process]` Orchestrator personally re-ran the deterministic checks.
- [ ] `[process]` Independent reviewer approved the evidence.

## Out of Scope

Chart redesign, sprite polish, animation retuning, and any engine/content change. A failed check
creates a narrowly scoped fix ticket; verification agents do not edit production code.
