## Context

The only currency is coins. `spendCoins` is safe and persistent but has zero callers, so the purse
only rises. There is no harbor route, product catalog, or purchase receipt.

## Planning Decisions

- **[locked-decision]** “Tokens” means the existing coins; no second currency is introduced.
- **[locked-decision]** Mastery-earned cannons are not sold directly. Spending may buy a chest that
  uses A-032's `settleStoreChest` contract, preserving the learning loop.
- **[locked-decision]** The demo inventory is one repeatable chest for `50` coins, held in the
  named engine constant `HARBOR_CHEST_PRICE`. It is above the maximum common chest coin result and
  is roughly one strong-win purse. No stat parts or repair kits ship because hull already resets.

## Acceptance Criteria

- **AC-1**: Given the owner-approved catalog, when the harbor lists products, then every price is a
  positive named tuning value and the existing coin balance is displayed as the only currency.
- **AC-2**: Given sufficient coins, when a chest is bought, then coins are deducted exactly once
  and the handler passes its captured `nextPurchaseSequence` plus `HARBOR_CHEST_PRICE` to A-032,
  which returns one truthful persisted reward receipt.
- **AC-3**: Given insufficient coins, repeated tap, remount, or purchase failure, when buying, then
  a repeated handler intent reuses its sequence, remount only reads the retained receipt, neither
  balance nor inventory changes, and an actionable message is returned.
- **AC-4**: Given a mastery-earned cannon, when products are inspected, then it is not directly
  purchasable.
- **AC-5**: Given a completed purchase, when the app relaunches, then spent coins and any acquired
  cannon persist; the gun deck shows an acquired cannon as new.
- **AC-6**: Given a child-facing purchase control, then it says “coins” and “game chest,” contains
  no real-money language, and exposes a 64pt target.

## Test Plan

- Unit (deterministic): catalog, affordability, atomic/idempotent receipt, failure cases, and
  mastery-cannon exclusion.
- Native evidence: buy, insufficient funds, relaunch, and gun-deck NEW badge.

## Definition of Done

- [ ] Store inventory and `HARBOR_CHEST_PRICE = 50` are frozen before implementation.
- [ ] Tests are RED, independently reviewed, and frozen before implementation.
- [ ] No real-money, in-app-purchase, or external checkout surface exists.
- [ ] Local gates, native smoke, code review, and Security Agent review pass.

## Out of Scope

Payments, ads, repair kits, stat parts, cosmetics, bundles, dynamic pricing, or a second currency.
