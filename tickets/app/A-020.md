## Context

The Expo account is authenticated, but `npx eas-cli project:info` exits with `EAS project not
configured`. The repository has no `expo.extra.eas.projectId`, so the first deployment cannot be
addressed until `eas init` links or creates the Cannon Academy project. This ticket freezes that
single configuration contract before the CLI is permitted to edit `app.json`.

## Acceptance Criteria

- **AC-1**: Given the committed Expo configuration, when release tooling reads `app.json`, then
  `expo.extra.eas.projectId` exists and is a valid UUID rather than a placeholder.

## Required Release Evidence

- `npx eas-cli project:info` exits zero under the authenticated Expo account and identifies the
  `cannon-academy` project.
- No Expo token, password, callback code, or other credential is written to the repository.

## Test Plan

- Unit (deterministic, frozen): AC-1 reads the real `app.json`, proves the nested field exists, and
  validates its UUID shape. It must be RED before `eas init`.
- CLI verification (process): `project:info` after the link.

## Definition of Done

- [ ] `[process]` AC-1 was observed RED before implementation.
- [ ] `[process]` Frozen test passes after `eas init`.
- [ ] `[process]` `project:info` identifies the linked project.
- [ ] `[process]` Diff contains only the expected non-secret project metadata.
- [ ] `[process]` Reviewer and security review approved.

## Out of Scope

EAS Build profiles, App Store Connect, Firebase Auth, custom domains, and any application behavior.
