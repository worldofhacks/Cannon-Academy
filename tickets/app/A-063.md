## Reported

> "after each win of a duel, we should do a small animation of the ship going to the next island
> and then start the battle at the next island so the gameplay is more engaging and has stronger
> user retention."

## What is actually true

The ship teleports. `ChartShip` already runs Reanimated (bob via `useSharedValue` +
`withRepeat`, `ChartShip.tsx:38-93`) but its position is static props — berth computed per render
from the live island (`VoyageMap.tsx:271-280, 339-344`, focus at `layout.ts:117-122`). Nothing
observes "currentIsland changed" or "an island was just unlocked" as an animation trigger, and a
lifted fog is never announced — `victoryRewards` drops `unlockedIslands` on the floor
(`victoryRewards.ts:12-17`).

The geometry for a real sail already exists: island node centres (`board.ts:413-431`) and the
dotted trail between consecutive islands — a closed-form curve, linear interpolation plus
`sin(t·π)·bow` perpendicular offset with the bow sign alternating per leg
(`trailDots`, `board.ts:221-249`) — mapped to pixels via `mapX`/`mapY` (`layout.ts:48-55`).

Two documented traps:

- A worklet cannot call a JS closure (`ChartShip.tsx:66-71`): the curve must be pre-sampled into
  plain captured numbers before `useAnimatedStyle`.
- The chart's worklet inventory is frozen: `spec(A-018:AC-1)` pins **exactly seven**
  `useAnimatedStyle` callbacks by `file::binding` (`chart-worklet-safety.test.ts:468-476`); its
  own header says a new animation is added by deliberately editing the list.

## Fix

- A `sailProgress` shared value drives the ship between berths: from-berth, to-berth,
  perpendicular and bow captured as plain numbers (same formula as `trailDots`), one
  `withTiming` (~1800 ms, inOut easing), existing bob composed on top.
- Triggered in `app/chart.tsx` by diffing previous→next `currentIsland` (travel tap) and
  previous→next `unlockedIslands` (post-victory arrival), with the same double-fire discipline
  the settlement effect uses (`duel.tsx:139-141`) — one sail per arrival, StrictMode-safe.
- **Then the battle begins**: when the sail was an *arrival* (new island just unlocked), the
  chart sets the new island current and pushes the duel after a short beat (~600 ms), using the
  existing `chart→duel` push edge. When no new island exists (band ceiling reached, or a loss),
  no sail and no auto-battle — the chart behaves exactly as today.
- Add the new `file::binding` to `CURRENT_SHIPPED_WORKLETS` — the sanctioned eighth worklet.

## Acceptance criteria

- **AC-1**: On arrival (a win that opened an island) the ship animates from its previous berth to
  the new island's berth along the trail curve — never a teleport. A travel tap animates the same
  way between already-open islands.
- **AC-2**: The sail follows the printed trail: the animation's path function matches `trailDots`'
  curve — same interpolation, same perpendicular bow, same alternating sign per leg — asserted by
  sampling both at matching `t` values.
- **AC-3**: Exactly one sail per arrival: remount/StrictMode double-invocation does not replay
  it, and a re-render mid-sail does not restart it.
- **AC-4**: After an arrival sail completes, the duel at the new island starts on its own — the
  new island is current and the duel screen receives it. No auto-battle after a plain travel tap,
  after a loss, or when no new island exists.
- **AC-5**: The worklet inventory stays deliberate: the new binding is in
  `CURRENT_SHIPPED_WORKLETS`, the suite's every-other assertion passes unchanged, and no worklet
  closes over a JS function.

## Constraints

- The chart cannot render headless — follow the repo's AST-walking source-guard pattern for
  screen-level assertions (see `chart-worklet-safety.test.ts` and `design-fidelity.test.ts` for
  precedent); the curve math itself is pure and directly testable.
- Do not modify `services/chart.ts`, `Dock.tsx`, or `rewardSettlement.ts` (A-062 owns them).
  The arrival signal is the captain's `unlockedIslands` — which already changes today via
  mastery, so this ticket is testable before and after A-062 lands.
- Amending `CURRENT_SHIPPED_WORKLETS` is the only permitted edit to
  `chart-worklet-safety.test.ts`.
- Respect `HEADER`/dock-safe map bounds during the sail (`flow.ts` mapBounds) — the ship must not
  pass under the header pill or behind the dock at SE or Pro Max sizes.
