## Context

The single most important child-safety system in the game after the rank ratchet: PLAN.md's
promise that "variance can't convince a 6-year-old they're bad at math." Two modules.

**`mercy.ts` — the policy, pure and serialisable:**

```ts
export interface MercyState {
  readonly recentPlayerCorrect: readonly boolean[];  // most-recent-first, capped at BOT_ACCURACY_WINDOW
  readonly consecutiveLosses: number;
  readonly forcedMisfiresRemaining: number;
}
export const emptyMercyState: MercyState;
export function recordPlayerAnswer(m: MercyState, correct: boolean): MercyState;
export function recordDuelResult(m: MercyState, playerWon: boolean): MercyState;
export function playerRecentAccuracy(m: MercyState): number;      // [0,1]; empty history -> 0
export function targetBotAccuracy(m: MercyState, band: { min: number; max: number }): number;
export function consumeForcedMisfire(m: MercyState): MercyState;
```

- `recordPlayerAnswer` prepends and truncates to `BOT_ACCURACY_WINDOW`.
- `recordDuelResult(m, false)` increments `consecutiveLosses`; on reaching
  `MERCY_LOSS_STREAK_TRIGGER` (2) it sets `forcedMisfiresRemaining = MERCY_FORCED_MISFIRES` (2)
  and resets the streak to `0`. `recordDuelResult(m, true)` resets `consecutiveLosses` to `0`
  and leaves any pending forced misfires alone.
- `targetBotAccuracy` = `clamp(playerRecentAccuracy - BOT_MERCY_MARGIN, band.min, band.max)`,
  except with an **empty history**, where it returns `band.min` (start merciful).

**`bot.ts` — an `Opponent` (T-018) driven by the policy and the seeded PRNG:**

```ts
export function createBotOpponent(input: {
  readonly id: string;
  readonly loadout: readonly CannonId[];   // >= 1
  readonly accuracy: number;               // [0,1], typically from targetBotAccuracy
  readonly forcedMisfires: number;         // >= 0, typically from MercyState
  readonly rng: Rng;
}): Opponent;
```

- `chooseAction` picks a cannon from `loadout` via `pick(rng, …)`.
- `produceAnswer`: if forced misfires remain, return `correct: false` and decrement; otherwise
  `correct = nextFloat(rng) < accuracy`. `elapsedMs` is drawn with `nextInt` inside
  `[0, cannon.timerMs]` — **PRNG-drawn, never measured** (ARCHITECTURE.md §4.2).

## Planning Decisions

- `locked-decision` — the mercy rule itself: accuracy tracks the player's recent accuracy minus a
  margin, clamped to the band; two straight losses arm two forced misfires. PLAN.md states both.
- `open-question` — `BOT_MERCY_MARGIN`, `BOT_ACCURACY_WINDOW`, and `BOT_ACCURACY_BAND_BY_GRADE`
  have no values in either document. They are named T-004 constants; the ACs here pin the
  *relationships* (bot never above the player's recent accuracy once the clamp allows it, always
  inside the band, monotone in player accuracy) rather than any number. Raised for the human in
  `.tdd-swarm/traceability.md`.
- `proposed` — empty history returns `band.min`. Some starting value is required and the design's
  stated bias is mercy. Pinned by AC-5.
- `proposed` — forced misfires are consumed by the **bot**, one per wrong answer produced, and the
  count is passed in at construction. Keeping the counter out of `MercyState` during a duel means
  the duel does not have to thread mercy state through the reducer.
- `proposed` — `recordDuelResult(m, true)` does **not** clear pending forced misfires. A player who
  scrapes a win with mercy armed still gets the eased duel they were owed; clearing it would make
  the mercy grant depend on a coin flip.
- `proposed` — `elapsedMs` is uniform over `[0, timerMs]`. "Humanlike answer delays" (PLAN.md) has
  no specified distribution and the value is presentational — it enters the action log but does
  not affect the rival's damage, which uses the same `resolveShot` path with its own quality
  computation. Any richer distribution would be invented design.
- `proposed` — the bot holds its own `Rng` cursor internally, like the scripted opponent. It is
  never part of `DuelState`; replay reconstructs rival behaviour from the action log (T-023),
  not by re-running the bot.

## Acceptance Criteria

- **AC-1**: Given `emptyMercyState`, when inspected, then `recentPlayerCorrect` is empty,
  `consecutiveLosses` is `0`, `forcedMisfiresRemaining` is `0`, and `playerRecentAccuracy`
  returns `0` (not `NaN`).
- **AC-2**: Given `recordPlayerAnswer` applied `BOT_ACCURACY_WINDOW + 5` times, when the state is
  inspected, then `recentPlayerCorrect.length === BOT_ACCURACY_WINDOW` and its entries are the
  most recent answers, most-recent-first.
- **AC-3**: Given a history of 8 correct and 2 incorrect answers (with
  `BOT_ACCURACY_WINDOW >= 10`), when `playerRecentAccuracy` is called, then it returns `0.8`.
- **AC-4**: Given a player accuracy `p` and a band, when `targetBotAccuracy` is called, then the
  result equals `clamp(p - BOT_MERCY_MARGIN, band.min, band.max)`; in particular it is always
  within `[band.min, band.max]`, and whenever `p - BOT_MERCY_MARGIN` lies inside the band the
  result is strictly less than `p`.
- **AC-5**: Given `emptyMercyState`, when `targetBotAccuracy` is called with any band, then it
  returns `band.min`.
- **AC-6**: Given player accuracy sweeping `0 … 1` in steps of `0.05`, when `targetBotAccuracy`
  is computed for a fixed band, then the sequence is non-decreasing — a struggling player never
  faces a harder bot than a thriving one.
- **AC-7**: Given `emptyMercyState`, when `recordDuelResult(m, false)` is applied twice, then
  after the first call `consecutiveLosses === 1` and `forcedMisfiresRemaining === 0`, and after
  the second `forcedMisfiresRemaining === MERCY_FORCED_MISFIRES` (2) and `consecutiveLosses === 0`.
- **AC-8**: Given one loss followed by a win followed by a loss, when the state is inspected,
  then `forcedMisfiresRemaining === 0` — the streak must be *consecutive*.
- **AC-9**: Given a state with `forcedMisfiresRemaining === 2`, when `recordDuelResult(m, true)`
  is applied, then `forcedMisfiresRemaining` is still `2` and `consecutiveLosses === 0`.
- **AC-10**: Given every mercy function, when called, then the input `MercyState` is unmutated
  and the result is a new plain object that survives a JSON round-trip unchanged.
- **AC-11**: Given `createBotOpponent` with `accuracy: 0.6`, `forcedMisfires: 0`, and a fixed
  seed, when 10,000 answers are produced, then the observed correct rate is within `[0.58, 0.62]`
  and every result has exactly the keys `correct` and `elapsedMs`.
- **AC-12**: Given `createBotOpponent` with `accuracy: 1.0` and `forcedMisfires: 2`, when four
  answers are produced in sequence, then the first two are `correct: false` and the last two are
  `correct: true` — the mercy grant applies to exactly the next two answers.
- **AC-13**: Given `createBotOpponent` with `accuracy: 0.0`, when 100 answers are produced, then
  all are `correct: false`; given `accuracy: 1.0` and `forcedMisfires: 0`, then all 100 are
  `correct: true`.
- **AC-14**: Given a bot over 1,000 turns, when each `elapsedMs` is inspected, then it is an
  integer in `[0, cannon.timerMs]` for the cannon returned by the matching `chooseAction` call.
- **AC-15**: Given a bot with a 3-cannon loadout over 3,000 `chooseAction` calls with a fixed
  seed, then every returned `cannonId` is in the loadout and each of the three appears at least
  800 times.
- **AC-16**: Given two bots created with identical inputs including the same `Rng`, when both are
  driven through 200 turns, then their emitted `(cannonId, correct, elapsedMs)` sequences are
  element-wise identical; and a bot created with a different seed produces a different sequence.
- **AC-17**: Given `createBotOpponent` with an empty `loadout`, an `accuracy` outside `[0, 1]`, a
  negative `forcedMisfires`, or a `cannonId` absent from the catalog, when called, then it throws
  a `RangeError` or an `Error` naming the offending field.
- **AC-18**: Given `src/engine/opponents/bot.ts` and `mercy.ts`, when their source text is
  scanned, then neither contains `Date`, `Math.random`, `setTimeout`, `setInterval`, or
  `performance.now`. This scan is **secondary defence** — a substring grep cannot see
  `const { random } = Math`, which is exactly the refactor it exists to catch. The authoritative
  guard is the repo ESLint determinism block (identifier-reference based, covering both
  `src/engine/**` and `src/content/**` as of Phase 0, verified firing). Keep the scan.
- **AC-19**: Given a simulated 6-duel losing streak in which the player answers at 30% accuracy,
  when the bot accuracy is recomputed after each duel from the accumulated `MercyState`, then
  every computed accuracy stays within the band and never rises above the value computed for a
  player answering at 90% — the end-to-end mercy story PLAN.md promises.
