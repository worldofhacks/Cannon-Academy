## Context

Mastery is the progression spine and the one place where "the fun mode is never progression-dead"
is enforced: duelling advances a skill at half the rate of a gunnery-range drill, but it does
advance it.

```ts
export interface SkillMastery {
  readonly weightedCorrect: number; // range answers count 1.0, duel answers 0.5
  readonly correct: number; // raw count, for accuracy
  readonly attempts: number; // raw count, for accuracy
}
export type MasterySource = 'range' | 'duel';

export const emptyMastery: SkillMastery;
export function applyAnswer(m: SkillMastery, source: MasterySource, correct: boolean): SkillMastery;
export function accuracy(m: SkillMastery): number; // [0,1]; 0 attempts -> 0
export function meterPercent(m: SkillMastery): number; // integer [0, MASTERY_METER_MAX]
export function isMastered(m: SkillMastery): boolean; // weightedCorrect >= 10 AND accuracy >= 0.70
export function resolveUnlocks(input: {
  readonly mastery: Readonly<Partial<Record<SkillId, SkillMastery>>>;
  readonly unlockedCannons: readonly CannonId[];
  readonly unlockedIslands: readonly IslandId[];
}): { readonly cannons: readonly CannonId[]; readonly islands: readonly IslandId[] };
```

- `applyAnswer` always increments `attempts`; increments `correct` only when correct; adds
  `MASTERY_RATE_RANGE` (1.0) or `MASTERY_RATE_DUEL` (0.5) to `weightedCorrect` only when correct.
- `meterPercent = min(MASTERY_METER_MAX, round(100 * weightedCorrect / MASTERY_THRESHOLD_CORRECT))`.
- `resolveUnlocks` returns only _newly_ unlocked ids — never anything already in the input lists.
  - **Cannons:** every cannon whose `unlock.kind === 'range'` and whose `skill` is now mastered.
  - **Islands:** every island `I` with `requiresIsland === J` where at least one skill in
    `J.rangeSkills` is mastered.

## Planning Decisions

- `locked-decision` — threshold is `weightedCorrect >= 10` **and** `accuracy >= 0.70`, both
  inclusive. PLAN.md: "10 correct at ≥70% accuracy". The `≥` is what makes a four-choice guesser
  (~25%) unable to advance, which is the stated defence of the multiple-choice input.
- `locked-decision` — range fills at full rate, duels at half.
- `proposed` — accuracy is **raw** `correct / attempts`, unweighted by source. PLAN.md does not
  say; weighting accuracy by source would let a duel-heavy player's accuracy drift from the
  actual answers they gave, which is the wrong thing to gate a learning threshold on.
- `proposed` — **one** mastered range skill on island `J` lifts the fog on the next island.
  PLAN.md: "Crossing a threshold ... unlocks that skill's next cannon **and** lifts the fog on
  the next island" — a single crossing, so requiring all of `J.rangeSkills` would contradict it.
- `proposed` — `resolveUnlocks` is idempotent and returns only deltas, so a caller can apply it
  after every answer without duplicating unlocks.
- `proposed` — mastery is stored as counters (`weightedCorrect`, `correct`, `attempts`), with
  the 0-100 meter derived. ARCHITECTURE.md §5 persists `mastery: {skillId: 0-100}`; deriving the
  percentage keeps the threshold check exact and leaves the persisted projection to the store
  layer, which is out of this swarm's scope.

## Acceptance Criteria

- **AC-1**: Given `emptyMastery`, when inspected, then `weightedCorrect === 0`,
  `correct === 0`, `attempts === 0`, `accuracy` is `0` (not `NaN`), `meterPercent` is `0`, and
  `isMastered` is `false`.
- **AC-2**: Given `emptyMastery`, when `applyAnswer(m, 'range', true)` is applied, then
  `weightedCorrect === 1`, `correct === 1`, `attempts === 1`. When
  `applyAnswer(m, 'duel', true)` is applied instead, then `weightedCorrect === 0.5`,
  `correct === 1`, `attempts === 1`.
- **AC-3**: Given any mastery, when `applyAnswer(m, source, false)` is applied for either
  source, then `weightedCorrect` is unchanged, `correct` is unchanged, and `attempts` increases
  by exactly `1`.
- **AC-4**: Given `applyAnswer`, when called, then the input object is not mutated — the result
  is a new object and the input's fields are unchanged.
- **AC-5**: Given 20 correct duel answers, when compared to 10 correct range answers, then both
  reach `weightedCorrect === 10` — a duel answer is worth exactly half a range answer.
- **AC-6**: Given a mastery of exactly `weightedCorrect = 10`, `correct = 7`, `attempts = 10`
  (accuracy exactly `0.70`), when `isMastered` is called, then it returns `true` — both
  thresholds are inclusive.
- **AC-7**: Given `weightedCorrect = 9.5` with accuracy `1.0`, then `isMastered` is `false`.
  Given `weightedCorrect = 12` with `correct = 12, attempts = 18` (accuracy `0.6667`), then
  `isMastered` is `false`. Both thresholds must hold.
- **AC-8**: Given `weightedCorrect` sweeping `0 … 20` in steps of `0.5`, when `meterPercent` is
  computed, then every value is an integer in `[0, 100]`, the sequence is non-decreasing,
  `meterPercent` is `100` for every `weightedCorrect >= 10`, and it is `50` at
  `weightedCorrect === 5`.
- **AC-9**: Given `accuracy` with `attempts = 0`, then it returns `0`. Given `correct = 3,
attempts = 4`, then it returns `0.75`.
- **AC-10**: Given a mastery map in which `add_within_20` is mastered and nothing is yet
  unlocked, when `resolveUnlocks` is called, then the returned `cannons` contains `six_pounder`
  and does not contain `chain_shot` (whose skill `sub_within_20` is not mastered) or
  `nine_pounder` (whose `unlock.kind` is `chest`, not `range`) or either starter cannon.
- **AC-11**: Given `add_within_20` mastered and `six_pounder` already in `unlockedCannons`, when
  `resolveUnlocks` is called, then `cannons` is empty — only new unlocks are returned.
- **AC-12**: Given `add_within_20` mastered (a `port_sumwich` range skill) and only
  `port_sumwich` in `unlockedIslands`, when `resolveUnlocks` is called, then `islands` is exactly
  `[isla_products]` — the fog lifts on the immediate successor only, not on every later island.
- **AC-13**: Given an empty mastery map, when `resolveUnlocks` is called, then both `cannons`
  and `islands` are empty and no error is thrown.
- **AC-14**: Given the same input, when `resolveUnlocks` is called twice and the first result is
  merged into the unlocked lists before the second call, then the second call returns empty
  lists for both — the function is idempotent under application.
- **AC-15**: Given a `SkillMastery` value, when round-tripped through
  `JSON.parse(JSON.stringify(m))`, then `accuracy`, `meterPercent`, and `isMastered` all return
  the same results as for the original.

## Pre-freeze note from the Test Agent (orchestrator-verified, 2026-07-28)

**The island-unlock rule does not gate on the predecessor's own unlock status.** The stated rule —
unlock island `I` where `I.requiresIsland === J` and at least one skill in `J.rangeSkills` is
mastered — reads `unlockedIslands` only to exclude already-unlocked islands from the delta, never
as a precondition that `J` itself is unlocked. So mastering `isla_products`' range skill lifts
`quotient_cove`'s fog even if neither island is currently unlocked. The Test Agent froze a test
proving this literal reading rather than silently over-constraining it.

**Orchestrator probe — not currently exploitable:**

```
isla_products.rangeSkills: mult_facts
  mult_facts (grade 3), taught ONLY by twelve_pounder [unlock.kind = range, at isla_products]
```

The sole cannon teaching that skill is unlocked _at the island that teaches it_, so a player cannot
master it without having reached there. Grade-band placement pre-unlocks islands and cannons
together, so it opens no skip path either.

**It is a latent trap, though.** The moment a chest drop grants a range cannon out of band — T-009
rolls chest contents, and PLAN.md §Treasure chests lists cannons as a drop type — a K-1 player
holding `twelve_pounder` could leap two islands. Whoever implements chest cannon selection should
either exclude out-of-band range cannons or the island rule should gain the predecessor
precondition. Recorded here so the reviewer sees it and it is not rediscovered in wave 5.
