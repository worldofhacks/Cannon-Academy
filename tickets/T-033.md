## Context

L-023 records that the frozen-test guard was moved from the PreToolUse hook to an **outcome** gate in
`run-local-gates.sh`, because a hook cannot see a shell write. The gate was written. It has never
executed. Three independent faults, any one of which is sufficient:

1. **It is unreachable.** `exit "$FAIL"` is line 49; the gate block starts at line 50. The script
   always exits before reaching it.
2. **It calls an undefined function.** The block calls `report PASS ...` / `report FAIL ...`.
   `run-local-gates.sh` defines `run()`, not `report()` — no `report()` exists anywhere in
   `.tdd-swarm/*.sh`. Were it reachable, it would die with `command not found`.
3. **Its guard condition is never true.** The block is wrapped in
   `[ "$(cat .tdd-swarm/phase 2>/dev/null)" = "implement" ]`, and **`.tdd-swarm/phase` does not
   exist** in the repo. Nothing writes it.

The wave-3 gate run confirms the outcome: `run-local-gates.sh` printed seven gate lines
(`format`, `lint`, `typecheck`, `unit`, `no-todos`, `no-skipped-tests`, `engine-purity`) and no
`frozen-tests-unmodified` line at all.

## Why this matters more than a typo

The wave-3 dispatch brief stated as ground truth: _"Zero test files were modified by any
implementer — now enforced mechanically."_ The first half is true — verified independently for this
wave by diffing `__tests__` across the merge, which shows six `A` entries and zero `M`. The second
half is false. Six implementers were believed to be under a mechanical guard that was not running,
and the belief was load-bearing in the decision to merge.

This is [[L-007]] exactly: a guard's real coverage is what it has been **observed blocking**. This
one has been observed doing nothing, because it produces no output either way — a silent gate is
indistinguishable from an absent one.

## Acceptance Criteria

- **AC-1**: Given the gate block, when `run-local-gates.sh` runs, then a `frozen-tests-unmodified`
  line is printed on every invocation — moved above `exit "$FAIL"`.
- **AC-2**: Given the gate block, when it reports, then it uses the script's existing reporting
  path (`run`/`printf`) and no undefined `report` function remains.
- **AC-3**: Given the phase guard, when the gate runs, then either `.tdd-swarm/phase` is actually
  written by the orchestrator at phase entry, or the guard is removed so the gate is
  unconditional. A guard keyed to a file nothing creates is equivalent to `false`.
- **AC-4**: Given a deliberately modified frozen test file committed under a `feat(...)` message,
  when the script runs, then it exits non-zero and names the offending file — **the gate must be
  observed failing on a real violation before it is trusted** (L-007, L-014).
- **AC-5**: Given a test file changed under a `test(...)` or `style(...)` commit, when the script
  runs, then the gate passes — the legitimate TDD path is not blocked.
