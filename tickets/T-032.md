## Context

Found by the wave-3 integration probe — the first time `placement.ts` and `mastery.ts` ran in one
process. Each module satisfies its own acceptance criteria exactly; the gap only exists in
composition, so neither frozen suite could have caught it.

`resolvePlacement` pre-grants every cannon whose `unlock.kind` is `starter` **or `range`** and whose
`minGrade <= maxGrade` (T-011 AC-2, AC-4). `resolveUnlocks` then awards range cannons on skill
mastery, minus anything already owned (T-010 delta semantics). The second set is largely a subset of
the first.

Measured against the shipped catalog, with **every skill mastered**:

```
range-unlock cannons in catalog: six_pounder, chain_shot, twelve_pounder,
                                 mortar, double_broadside, powder_keg, long_nine   (7)

band   owned at placement   range guns pre-granted   still earnable by mastery
k_1            4                   2 / 7             5 cannons, 4 islands
g2_3           7                   5 / 7             2 cannons, 2 islands
g4_5           9                   7 / 7             0 cannons, 0 islands
```

**A `g4_5` captain can never earn a cannon or an island through range mastery.** Placement hands
over all seven range guns and all five islands at onboarding, so `resolveUnlocks` returns empty
forever. The mastery meter still fills and still gates nothing. That is the band PLAN.md
specifically designed placement for ("so a 5th grader begins at multiplication, not 3+4"), and it is
the band where the progression reward is fully consumed.

`g2_3` is degraded rather than empty; `k_1` is intact.

## The tension

PLAN.md asks placement to do two things that pull apart at the top band:

- "pre-unlocks islands and cannons up to the player's band" — so a 5th grader is not grinding
  through `3 + 4` to reach multiplication.
- range mastery is the path by which cannons are earned.

At `g4_5` the first swallows the second whole. Nothing in either ticket is wrong; **the boundary
between them was never specified.**

## Planning Decisions

- `open-question` (**owner decision required — do not implement before it lands**) — which of these
  the game wants:
  1. **Placement grants `starter` only; range guns stay earnable at every band.** Preserves the
     reward loop everywhere. Costs the "begins at multiplication" promise unless islands stay
     pre-unlocked independently of cannons — i.e. split the island rule from the cannon rule.
  2. **Placement grants access, mastery grants power.** Keep pre-granting, and give range mastery a
     different reward at higher bands (coins, chest tier, rank progress) so the meter still pays.
  3. **Accept it.** Declare progression a K-1/G2-3 mechanic and let `g4_5` run on rank and economy
     alone. Cheapest, and defensible — but it should be a decision on the record, not an accident.

- `proposed` — whichever option wins, the composition gets a test that pins it. Today no test in
  either suite asserts anything about the two functions _together_, which is precisely why this
  survived six green gate runs and two approving code reviews.
