## Context

`validateCatalogs({ skills, cannons, islands, ranks, crew })` currently delegates entirely to the
T-003 zod schemas. Those validate each **entry** in isolation, so every **set-level** corruption
passes:

- duplicate ids within a catalog
- a dangling cross-reference — an id that is enum-legal but absent from the sibling catalog
  (e.g. `cannon.unlock.island: 'grandline'` when `islands.json` omits that entry)
- a missing entry the id union declares
- duplicate rank `tier` values
- an `island.requiresIsland` cycle

The sharpest form of the gap: the ratified signature takes **all five catalogs in one object**,
which implies a cross-catalog check the function never performs.

**Why this is a follow-up rather than a T-006 defect.** The T-006 implementer's Iron Law call was
judged defensible on review: every one of those invariants _is_ enforced against the shipped
catalogs by the frozen suite (T-006 AC-2, AC-9, AC-10), so a corrupt catalog fails a test before
it can reach a device, and nothing downstream calls `validateCatalogs` today. The function is
weaker than its signature implies, but nothing is currently unprotected.

**Why it is still worth doing.** The protection lives in the _test suite_, not the _function_. The
first consumer to call `validateCatalogs` on catalogs the suite does not cover — a future editor
tool, a modding path, or a catalog loaded at runtime — inherits a validator that silently accepts
a broken set.

## Acceptance Criteria

- **AC-1**: Given a catalog set with a duplicate id in any of the five catalogs, when
  `validateCatalogs` is called, then it throws an `Error` naming the catalog and the duplicated id.
- **AC-2**: Given a `cannon.unlock.island` naming an island absent from `islands.json`, then it
  throws naming both the cannon id and the missing island id.
- **AC-3**: Given an `island.rangeSkills` or `unlocksCannons` entry absent from its sibling
  catalog, then it throws naming the island and the missing id.
- **AC-4**: Given two ranks sharing a `tier`, then it throws naming both rank ids.
- **AC-5**: Given `island.requiresIsland` forming a cycle, then it throws naming the islands in
  the cycle.
- **AC-6**: Given the shipped catalogs, then `validateCatalogs` does **not** throw — the existing
  behaviour is unchanged for valid input.
- **AC-7**: Given any of the above, then the message is specific enough for a catalog author to
  locate the offending line without reading the validator.

## Definition of Done

- [ ] Set-level checks implemented in `validateCatalogs`
- [ ] Every rejection names the catalog and the offending id(s)
- [ ] Shipped catalogs still validate; all existing T-006 tests pass unchanged
- [ ] Local gates green

## Out of Scope

- Changing the ratified one-argument signature.
- Any change to the schemas (T-003) or the catalog data (T-006).
- Bidirectional unlock agreement beyond existence — the frozen suite already asserts it against
  the shipped data; this ticket is about the function, not the data.
