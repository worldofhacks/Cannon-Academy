## Context

`.tdd-swarm/posture.md` names this the **highest-value gate in the project**. T-014 / T-015 /
T-016 each sweep their own three files; this ticket owns the two things none of them can:
the registry that makes every template discoverable, and the cross-skill properties that only
exist once all nine files are present.

**The registry:**

```ts
// src/content/templates/index.ts
export const templatesBySkill: Readonly<Record<SkillId, readonly Template[]>>;
export const allTemplates: readonly Template[];
export function templatesForSkill(skill: SkillId): readonly Template[];   // total; throws on empty
```

It imports all nine JSON files by explicit path (no globbing — the bundler must see every
import), parses each through `z.array(templateSchema)` at module load, and throws on failure.
`Record<SkillId, …>` rather than `Partial<…>` is deliberate: adding a `SkillId` in T-003 becomes
a **type error** here until a template file exists for it.

**The catalog-wide golden sweep** re-runs ARCHITECTURE.md §9.1 across `allTemplates`, which is
what catches the failure mode the per-band tickets structurally cannot: a template file that
exists, passes its own ticket's suite, and is never registered.

## Planning Decisions

- `proposed` — explicit imports, no dynamic file discovery. The engine must bundle cleanly under
  Metro (ARCHITECTURE.md §1) and content ships in the bundle with no filesystem at runtime.
- `proposed` — `Record<SkillId, …>`, not `Partial`. A missing skill should break the build, not
  produce an empty pool at runtime for a child standing at a gunnery range.
- `locked-decision` — 1,000 seeded samples per template (ARCHITECTURE.md §9.1, posture.md).
- `proposed` — the per-band tickets keep their own sweeps. The duplication is deliberate: it
  gives each template author a fast local signal, and it means a wave-5 regression here points at
  the registry rather than at content.
- `open-question` — templates per skill. ARCHITECTURE.md §4.1 says 15–25; PLAN.md's day-3
  deliverable says a "≥8 templates/skill floor". AC-3 enforces **≥8**, the explicitly written
  floor. Raised for the human in `.tdd-swarm/traceability.md`.

## Acceptance Criteria

- **AC-1**: Given `src/content/templates/index.ts`, when imported, then it loads without
  throwing and `templatesBySkill` has exactly one entry for each of the nine `SkillId` values,
  with no extra keys.
- **AC-2**: Given `allTemplates`, when compared to the concatenation of every
  `templatesBySkill` entry, then it contains exactly the same templates with no omissions and no
  duplicates.
- **AC-3**: Given each of the nine skills, when its template array is measured, then it has at
  least `8` entries.
- **AC-4**: Given `allTemplates`, when template `id`s are collected, then all are unique across
  the entire catalog, every id is non-empty, and every template's `skill` matches the
  `templatesBySkill` key it is filed under.
- **AC-5**: Given every template in `allTemplates`, when validated with `templateSchema`, then
  every one parses successfully.
- **AC-6**: Given every template whose `isWordProblem` is `true`, when its skill is looked up in
  `skills.json`, then that skill's `symbolicOnly` is `false` and its `minGrade >= 2` — PLAN.md's
  word-problem gate, checked across the whole catalog.
- **AC-7**: Given every skill whose `symbolicOnly` is `true`, when its templates are inspected,
  then none has `isWordProblem: true` — the same gate checked from the other direction.
- **AC-8**: Given every template in `allTemplates`, when 1,000 questions are generated from it
  with seeds `1 … 1000`, then every call succeeds without throwing; every sampled param is an
  integer inside its declared inclusive range; every declared constraint evaluates `true`; the
  rendered `text` contains no `{` or `}`; `choices.length === 4`; all four choice values are
  pairwise distinct; `choices[correctIndex].value` equals
  `evaluateNumber(template.answerExpr, params)`; and no choice value is `NaN` or non-finite.
- **AC-9**: Given the same catalog-wide sweep, when every generated distractor is checked against
  `isPlausibleDistractor(value, answer)` from T-005, then every one returns `true`.
- **AC-10**: Given the same sweep, when every correct answer is inspected, then it is finite and
  — for every skill except none — non-negative. No template in the K-5 catalog may produce a
  negative correct answer.
- **AC-11**: Given every cannon in `cannons.json`, when its `skill` is looked up in the registry,
  then `templatesForSkill(cannon.skill)` returns a non-empty array — every gun in the armory can
  actually be fired.
- **AC-12**: Given every island's `rangeSkills`, when each is looked up, then
  `templatesForSkill` returns a non-empty array — every gunnery range has drills.
- **AC-13**: Given `templatesForSkill` called with a value outside `SkillId`, when invoked, then
  it throws an `Error` naming the skill — never returns `undefined` or an empty array.
- **AC-14**: Given the same seed and the same skill, when `templatesForSkill` is called twice and
  each result is fed to `generateQuestion`, then the two questions are deeply equal — registry
  ordering is stable across calls and across module reloads.

## Test Plan

- Unit (deterministic): AC-1 … AC-5, AC-13, AC-14 — registry completeness, id uniqueness, schema
  validity, total lookup, and stable ordering. Split into `registry.test.ts`.
- Unit (deterministic): AC-6, AC-7 — the word-problem gate in both directions across the whole
  catalog. This is the test that protects a non-reading kindergartner.
- Unit (deterministic): AC-8, AC-9, AC-10 — the ARCHITECTURE.md §9.1 sweep over every registered
  template: ~72+ templates × 1,000 seeds. Split into `golden.test.ts`.
- Unit (deterministic): AC-11, AC-12 — cross-catalog reachability: no cannon and no gunnery range
  can exist without questions behind it.
- Eval: none. There is no LLM in this codebase; every sample is a pure function of a seed.

## Out of Scope

- **Authoring or editing any template.** If a template fails this suite, the fix belongs in
  T-014 / T-015 / T-016's file scope, not here — raise it rather than editing content.
- Changing `templateSchema`, the generator, the evaluator, or the distractor module.
- Runtime selection of which skill to draw from — the duel reducer (T-020) and drill (T-017)
  receive an injected pool.
- Performance measurement of generation (deferred under `mvp` posture, `.tdd-swarm/posture.md`)
  beyond the 60-second suite budget above.
- Any network or filesystem access at runtime — content is bundled (ARCHITECTURE.md §4.4).
